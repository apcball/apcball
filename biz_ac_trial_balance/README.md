# biz_ac_trial_balance — งบทดลอง (Trial Balance)

รายงานงบทดลองตามรูปแบบบัญชีไทย สำหรับ Odoo 17 Community
(Community ไม่มี `account_reports` ของ Enterprise จึงต้องมีเครื่องยนต์รายงานของตัวเอง)

## สิ่งที่ได้

| ทาง | ใช้เมื่อ |
|---|---|
| **หน้าจอ** — Accounting → Reporting → *งบทดลอง (Trial Balance)* | ดูสด คลิกแถวเจาะดูรายการ |
| **PDF** | ส่งผู้สอบบัญชี / แนบแฟ้มปิดงวด (A4 แนวนอน ฟอนต์ Sarabun ฝังในไฟล์) |
| **Excel** | ทำงานต่อ — ยอดรวมเป็นสูตร ตรวจย้อนได้ |

เมนู *พิมพ์งบทดลอง (PDF / Excel)* เปิดไดอะล็อกตัวกรองแล้วสั่งพิมพ์ได้โดยไม่ต้องเปิดหน้าจอ

## โครงสร้าง — เครื่องยนต์เดียว สามทางออก

```
biz.trial.balance.report.get_report_data(options)   ← แหล่งความจริงเดียว
   ├── OWL client action  biz_ac_trial_balance.trial_balance
   ├── QWeb PDF           report.biz_ac_trial_balance.report_trial_balance_doc
   └── XLSX               biz.trial.balance.xlsx.generate(options)
```

**ห้ามเพิ่มเส้นทางคำนวณเส้นที่สอง** ถ้าตัวเลขบนจอกับในไฟล์ที่ส่งออกไปคำนวณคนละที่
วันหนึ่งมันจะเพี้ยนจากกันโดยไม่มีใครรู้ตัว ทุกทางออกต้องเรียก `get_report_data()` เท่านั้น

การคำนวณใช้ ORM `_read_group` ไม่ใช่ raw SQL เพื่อให้ record rule และ multi-company
ทำงานตามปกติ (ต่างจาก `accounting_pdf_reports` ที่ประกอบ SQL เอง)

## หลายบริษัท (multi-company)

ค่าตั้งต้นคือบริษัทที่ติ๊กอยู่ใน **company switcher** มุมขวาบน (`env.companies`)
เปลี่ยนชุดบริษัทได้ 3 ทาง — **ช่องเลือกบริษัทบนแถบตัวกรองของหน้าจอ** (สะดวกสุด
ไม่ต้องออกจากรายงาน), company switcher, หรือระบุเองในไดอะล็อก *พิมพ์งบทดลอง*

ช่องเลือกบริษัทกินรายชื่อจาก `allowed_companies` ใน payload ซึ่งมาจาก
`user.company_ids` — เสนอเฉพาะบริษัทที่ผู้ใช้เข้าถึงได้จริง และติ๊กออกจนเหลือศูนย์
ไม่ได้ (จะโผล่ก็ต่อเมื่อผู้ใช้มีสิทธิ์มากกว่าหนึ่งบริษัท)

| โหมด | ผลลัพธ์ |
|---|---|
| **รวม** (`consolidated`, ค่าตั้งต้น) | บัญชี **รหัสเดียวกัน** ของทุกบริษัทยุบเป็นแถวเดียว ยอดบวกกัน คลิกเจาะแล้วเห็นรายการของทุกบริษัทในแถวนั้น |
| **แยก** (`split`) | 1 บัญชี 1 แถว มีคอลัมน์ *บริษัท* กำกับ ทั้งบนจอ PDF และ Excel |

ยอดรวมทั้งสิ้นของสองโหมดเท่ากันเสมอ (เป็นข้อมูลชุดเดียวกัน คนละวิธีจัดแถว)
สลับโหมดบนหน้าจอด้วยปุ่ม *แยกตามบริษัท* ซึ่งจะโผล่เมื่อรายงานครอบมากกว่าหนึ่งบริษัท

รายละเอียดที่ทำถูกไว้แล้ว:

* **สิทธิ์** — `_resolve_company_ids()` ปฏิเสธ (`AccessError`) ถ้าขอบริษัทที่อยู่นอก
  `user.company_ids` ตรวจกับสิทธิ์จริงของผู้ใช้ ไม่ใช่ชุดที่ติ๊กอยู่ตอนนั้น ตัวกรอง
  ที่บันทึกไว้ก่อนสลับ switcher จึงยังสั่งพิมพ์ได้
* **ปีบัญชีคนละวัน** — ยอดยกมาแบบ *ต้นปีบัญชี* จับกลุ่มบริษัทตามวันต้นปีบัญชีแล้ว
  ยิงทีละกลุ่ม (กลุ่มบริษัทไทยมักตรงกันจึงเหลือคิวรีเดียว)
* **กำไรสะสมยกมา** — ยกทีละบริษัทเข้าบัญชี `equity_unaffected` ของบริษัทนั้นเอง
  ถ้าบริษัทไหนไม่มีบัญชีนี้ ยอดจะไปโผล่เป็นบรรทัดเสมือน *กำไร(ขาดทุน)สะสมยกมา*
* **สกุลเงิน** — ออกแบบบนสมมติฐานว่าทุกบริษัทใช้ THB ถ้าเจอบริษัทที่สกุลเงินต่างจาก
  บริษัทหลัก รายงานยังออกให้ (บวกตรง ๆ ไม่แปลงค่า) แต่ขึ้นแบนเนอร์เตือนทั้งบนจอ
  PDF และ Excel — ดู `checks["mixed_currency"]`

## จุดที่เป็นเรื่องบัญชีไทยโดยเฉพาะ

1. **ลงยอดข้างเดียว** — ยอดยกมาและยอดคงเหลือของแต่ละบัญชีลงเดบิตหรือเครดิตข้างใดข้างหนึ่ง
   ไม่มีเลขติดลบในรายงานเลย ส่วนคอลัมน์ *เปลี่ยนแปลง* คงเดบิต/เครดิตดิบไว้ทั้งสองขา
2. **5 หมวดบัญชี** — สินทรัพย์ / หนี้สิน / ส่วนของเจ้าของ / รายได้ / ค่าใช้จ่าย
   map จาก `account.account.internal_group` ไม่ใช่จากเลขบัญชี จึงใช้ได้กับทุกผังบัญชี
3. **แถวรวมเป็นผลรวมของคอลัมน์ ไม่ใช่ยอดสุทธิ** — ยอดสุทธิของทั้งงบเป็นศูนย์เสมอตาม
   หลักบัญชีคู่ ถ้ายุบเป็นข้างเดียวแถวรวมจะกลายเป็น 0.00/0.00 และบวกยอดหมวดย่อยแล้ว
   ไม่ตรงกับแถวรวม ผู้สอบบัญชีตรวจย้อนไม่ได้
4. **ยอดยกมาต้นปีบัญชี → กำไรสะสม** — เมื่อบัญชี P&L เริ่มนับใหม่ ผลของปีก่อน ๆ ต้องยกไป
   บัญชี `equity_unaffected` ไม่งั้นงบไม่ดุล (Odoo Community ไม่สร้างรายการปิดบัญชีให้เอง)
   ถ้าผังบัญชีไม่มีบัญชีนั้น จะขึ้นเป็นบรรทัด *กำไร(ขาดทุน)สะสมยกมา* แทน
5. **หลังปิดบัญชี** — ยุบยอดรายได้/ค่าใช้จ่ายคงเหลือเข้ากำไรสะสมเป็นบรรทัด
   *กำไร(ขาดทุน)สุทธิยกไปกำไรสะสม* ใช้ได้ทั้งกรณีที่มีและไม่มีรายการปิดบัญชีจริง
6. **ตรวจดุล** — ชิปเขียว/แดงที่แถวรวม พร้อมชี้เลขที่เอกสารที่เดบิตไม่เท่าเครดิต
7. **ธงยอดผิดด้าน** — สินทรัพย์/ค่าใช้จ่ายมียอดเครดิต หรือหนี้สิน/ทุน/รายได้มียอดเดบิต
8. **% เปลี่ยนแปลง** — จากยอดยกมาไปยอดคงเหลือ ถ้ายอดยกมาเป็นศูนย์จะเว้นว่าง (คิดไม่ได้)
   ไม่แสดง 100% ซึ่งอ่านแล้วเข้าใจผิด
9. **พ.ศ.** บนหัวรายงานทั้ง PDF และ Excel
10. **ช่องลงนาม** ผู้จัดทำ / ผู้ตรวจสอบ / ผู้อนุมัติ ที่ท้าย PDF หน้าสุดท้าย

## Dependencies

* `account`
* `xlsxwriter` (มากับ image `odoo:17.0` อยู่แล้ว)

โมดูลนี้ไม่พึ่งโมดูล biz ตัวอื่นเลย — ตัวจัดรูปแบบตัวเลขอยู่ที่
`static/src/trial_balance/tb_format.js` และ design token ประกาศไว้ใน
`trial_balance.scss` เอง งบทดลองแสดง **1 บัญชี 1 แถว** ไม่มีบัญชีคลุม/บัญชีย่อย

**ตรวจแบบ soft (ไม่ใส่ใน depends):** `account.move.is_year_end_closing` จาก
`biz_year_end_closing` — ถ้ามี ตัวกรอง *ก่อนปิดบัญชี* จะตัดรายการปิดบัญชีสิ้นปีออกจริง ๆ

## ฟอนต์ไทยใน PDF

คอนเทนเนอร์ `odoo:17.0` **ไม่มีฟอนต์ไทยติดตั้งเลย** ถ้าไม่ฝังฟอนต์ ตัวอักษรไทยจะเป็น
กล่องว่างทั้งหน้า โมดูลนี้จึงฝัง Sarabun เป็น base64 ตรงใน CSS
(`report/trial_balance_pdf.py` → `SARABUN_FONT_CSS`)

⚠️ **ห้ามใส่ single-quote รอบชื่อ family หรือรอบ `format(truetype)`** — QWeb จะ escape
`'` เป็น `&#39;` แล้ว wkhtmltopdf อ่าน `@font-face` ไม่ออก ฟอนต์จะไม่ถูกฝังโดยไม่มี error
