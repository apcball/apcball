## Forecast — พยากรณ์รายเดือนทั้งวงจรธุรกิจ (v17.0.5.0.0)

แท็บเดียวสี่มุมมอง (สลับด้วย pill): **เงินสดรายเดือน · กำไรขาดทุน · งานขาย ·
ต้นทุนคงเหลือ** ครอบคลุมสายธุรกิจตั้งแต่ ออกแบบ → ขาย → ผลิต/จ้างช่วง →
ติดตั้ง → เก็บเงินเป็นงวด → จ่ายผู้รับเหมา

**สามชั้นของความแน่นอน** (ผสมในกริดเดียวแต่แยกให้เห็นบนจอ — แถวชั้นที่ 2
เป็นตัวเอียงสีจาง):

1. **ผูกพันแล้ว** — ลูกหนี้/เจ้าหนี้คงค้าง, แผนวางบิลลูกค้า (`bill_date` +
   รอบเก็บเงินของบริษัท), แผนจ่ายผู้รับเหมา (`expected_pay_date`), เงินประกัน,
   PO วัสดุ, งบ BOQ ที่ยังไม่เปิด PO, มูลค่างานตามสัญญาที่ยังไม่รับรู้,
   ต้นทุนคงเหลือ (EAC − ที่ใช้ไปแล้ว)
2. **งานขายที่ยังไม่เซ็น** — `biz.smart.finance.deal` × ความน่าจะเป็น
   กระจายตามแบบแผนวางบิล (`biz.smart.finance.billing.pattern`) นับจากเดือนที่
   คาดว่าจะเซ็น
3. **รายการประจำที่กรอกมือ** — Cash Flow Lines สถานะ "ใช้งาน"

**กติกากันนับซ้ำ** (docstring ของ `_build_forecast` มีตารางเต็ม): แผนวางบิล
นับเฉพาะงวดที่ยังไม่วางบิล · แผนจ่ายนับเฉพาะงวดที่ยังไม่มี vendor bill · PO
นับเฉพาะส่วนที่ยังไม่ตั้งบิล · งบ BOQ นับเฉพาะที่ยังไม่มี PO และหักยอดแผนจ่าย
ของโครงการออกก่อน · **ดีลที่ชนะต้องผูกโครงการ (constraint บังคับ) แล้วระบบเลิก
นับดีลทันที** · รายการกรอกมือที่ยังเป็นร่างจาก AI ไม่เข้ากริด · รายได้ตามสัญญา
นับเฉพาะงานที่ถือมูลค่า (`carries_boq_value`) ซึ่ง core การันตีว่ามีรายการละ 1 งาน

**คอลัมน์ "หลังจากนี้"** ท้ายกริดดูดทุกอย่างที่ตกหลังช่วงพยากรณ์ — ต่างจากกริด
13 สัปดาห์ของแท็บ Cash ที่ทิ้งเงินเลย horizon เงียบ ๆ (เทส `conservation`
ยืนยันว่า Σ ทุกคอลัมน์ = Σ ข้อมูลนำเข้า) ช่วงพยากรณ์ตั้งได้ 6–18 เดือนต่อบริษัท

**ภาพนิ่ง** `biz.smart.finance.forecast.snapshot` — cron รายเดือนเก็บกริดเป็น
JSON ต่อบริษัท (ซ้ำวันเดิมไม่สร้างซ้ำ) ไว้เทียบว่า "ตอนนั้นเราคาดว่าอย่างไร"

**AI ช่วยร่าง** ปุ่ม "ให้ AI ร่าง forecast" (manager) → `suggest_forecast` อ่าน
ยอดจริงรายเดือนย้อนหลัง 24 เดือน + กริดปัจจุบัน + ดีลที่เปิดอยู่ แล้วสร้าง
Cash Flow Lines เป็น **ร่าง** พร้อมเหตุผล (`ai_note`) ให้คนกดยืนยันก่อนเข้ากริด
พร้อม `assumption_notes` และ `probability_flags` (ดีลที่ความน่าจะเป็นดูไม่สมเหตุผล)

## ปีงบ สกุลเงิน และการปิดงวด (v17.0.3.0.0)

- **ปีงบไม่ตรงปีปฏิทินได้** — อ่านจาก `res.company.fiscalyear_last_day/month`
  ผ่าน `compute_fiscalyear_dates()` ของ core; `FY2026` หมายถึงปีงบที่**สิ้นสุด**
  ในปี 2026 (บริษัทที่ปิด 31 ธ.ค. จึงได้ 1 ม.ค.–31 ธ.ค. เหมือนเดิมทุกประการ)
  ถ้ามีระเบียน `account.fiscal.year` (om_fiscal_year) ครอบวันสิ้นปีงบอยู่
  ระบบจะใช้ช่วงนั้นแทน — รองรับปีงบสั้น/ยาวผิดปกติ
- **ตัวกรอง "ถึงงวด" เป็นงวดบัญชี P1..P12 ตามปีงบจริง** (แบบ SAP posting
  period) ไม่ใช่เดือนปฏิทินตายตัว รายการงวดมาจาก server เสมอ
- **แปลงค่าเงินเพื่อคอนโซลิเดต** — กลุ่มที่มีหลายสกุลจะถูกแปลงเป็นสกุลของ
  บริษัทที่เลือก (ดูรวมกลุ่ม = สกุลของบริษัทหลัก) ใช้ **closing rate หนึ่ง
  อัตราต่อหนึ่งคอลัมน์รายงาน**: คอลัมน์งวดนี้ใช้อัตรา ณ วันสิ้นงวด คอลัมน์
  งวดก่อนใช้อัตรา ณ วันสิ้นงวดก่อน จึงทำให้งบดุลยังดุลและ identity ของงบ
  กระแสเงินสดยังปิด (ดูข้อจำกัดท้ายไฟล์)
- **รู้ว่างวดปิดแล้วหรือยัง** — อ่าน `_get_user_fiscal_lock_date()` ของ core
  ถ้าล็อกคลุมถึงวันที่รายงาน จะขึ้นป้าย "ปิดงวดแล้ว" บนแถบเครื่องมือ

  ฟอนต์ไทย ถ้าไม่ฝังจะได้กล่องว่างทั้งหน้า) หัวตารางซ้ำทุกหน้า ไม่ตัดแถว
  คาหน้า และบล็อกลายเซ็นอยู่หน้าสุดท้ายเสมอ

## Compare (BI) — เปรียบเทียบหลายงวด (v17.0.4.2.0)

เทียบ **P&L สรุป + ฐานะการเงินย่อ + อัตราส่วน** สูงสุด 6 ช่วงเรียงเป็นคอลัมน์
เก่า → ใหม่ โดยคอลัมน์ขวาสุดคือ "ถึงงวด" ที่เลือกใน toolbar เสมอ

- **โหมด** — `รายเดือน` (1 คอลัมน์ = 1 งวดบัญชี), `รายไตรมาส` (3 งวดบัญชี =
  ไตรมาสของ*ปีงบ* ไม่ใช่ไตรมาสปฏิทิน), `รายปีงบ` (FYTD ถึงงวดลำดับเดียวกันของ
  แต่ละปีงบ — เทียบปีที่ยังไม่จบกับปีเต็มจะอ่านว่า "ตก" ทั้งที่ยังไม่ครบปี)
- **ไม่มีคอลัมน์ไหนยื่นเกิน as-of** ที่เลือก ไตรมาสปัจจุบันที่ยังไม่ครบจะถูกตัด
  และติดป้าย "ยังไม่ครบงวด" ในหัวคอลัมน์
- **อัตราแลกเปลี่ยนหนึ่งอัตราต่อหนึ่งคอลัมน์** — closing rate ณ วันสิ้นคอลัมน์
  นั้น ๆ (กติกาเดียวกับ Statements ดู `_fx_rates`)
- P&L = ยอดไหลในหน้าต่างคอลัมน์ · งบดุล = ยอดสะสม ณ วันสิ้นคอลัมน์ ·
  Δ% เทียบคอลัมน์ก่อนหน้า (ฐานเป็นศูนย์ = "—" ไม่ปลอมเปอร์เซ็นต์)
- **สีของ Δ% ตัดสินที่ engine** (`COMPARE_GOOD_WHEN_UP`) — รายได้/กำไร/เงินสด/
  ทุน เพิ่ม = เขียว ส่วนต้นทุน ค่าใช้จ่าย เจ้าหนี้ หนี้สิน **และเงินทุนที่จมใน
  ลูกหนี้/สต๊อก** เพิ่ม = แดง
- **Interactive**: คลิกชื่อแถว (หรือ chip) เพื่อสลับกราฟ — แถวเงินขึ้นเป็นแท่ง
  แถว % ขึ้นเป็นเส้น; คลิกตัวเลข (หรือแท่ง) เจาะดู `account.move.line` ที่ถูก
  จำกัดด้วยช่วงวันของคอลัมน์นั้นตรง ๆ; ปุ่ม "แสดง Δ% / เฉพาะยอด" เป็น client
  ล้วน มีแต่การเปลี่ยนโหมด/จำนวนช่วงที่ยิง server ใหม่
- **ปิดอยู่เป็นค่าตั้งต้น** (`compare_mode` ว่าง) — payload คืน stub และ
  **ไม่ยิงคิวรีเพิ่มแม้แต่ครั้งเดียว** ผู้ใช้เดิมและ PWA จึงไม่จ่ายอะไร
  เปิดแล้วใช้ ≤ 2 aggregate query ต่อคอลัมน์
- **เข้าไฟล์ส่งออกด้วย** — เปิดโหมดไว้แล้วกด Excel จะได้แผ่น "เปรียบเทียบ"
  เพิ่ม (กำไรขั้นต้น/สุทธิ และอัตราส่วนทุกตัวเป็น**สูตรจริง**อ้างเซลล์รายได้
  พร้อม `IF(...=0,"",…)` กันหารศูนย์) ส่วน PDF ได้บล็อกตารางเพิ่มหนึ่งบล็อก
  ปิดโหมดไว้ = ไฟล์เหมือนเดิมทุกประการ ไม่มีแผ่น/บล็อกส่วนเกิน

## Sales Channel — วิเคราะห์ช่องทางขาย (v17.0.11.1.0)

งบกำไรขาดทุน **รายเดือนทั้งปีงบ แยกตามช่องทางขาย** ตามเวิร์กชีตที่ทีมการเงิน
ใช้จริง (รายได้กางเป็นสาขา · ต้นทุน/SG&A กางเป็น "ประเภทต้นทุน" · มีบรรทัด
อัตรากำไรขั้นต้น/SG&A/EBIT เป็น % ของรายได้)

- **มิติช่องทางเลือกได้บนจอ 3 แบบ** — `ลูกค้าเชน / สาขา` (commercial partner,
  ค่าตั้งต้น) · `ทีมขาย` (`account.move.team_id`) · `ศูนย์ต้นทุน` (analytic
  distribution ของ plan ที่เลือกร่วมกับแท็บ Controlling)
- **กติกาปันยอด: GL จริงก่อน ที่เหลือเฉลี่ยตามรายได้**
  - ยอดที่ผูกมิติได้จาก GL = ยอดจริงของช่องทางนั้น
  - **รายได้ที่ผูกไม่ได้ไม่เฉลี่ย** — ค้างที่แถว "ไม่ระบุช่องทาง" (รายได้เป็น
    ตัวหารของการเฉลี่ย จะเอาตัวเองมาเฉลี่ยตัวเองไม่ได้)
  - ต้นทุน/ค่าใช้จ่ายที่ผูกไม่ได้ (SG&A ส่วนกลาง, บริษัทที่อ่าน GL จากระบบ
    ภายนอกซึ่งไม่มีมิติช่องทางเลย) เฉลี่ยตามสัดส่วน**รายได้ของเดือนนั้น**
    (เดือนที่ยังไม่มีรายได้ใช้สัดส่วนทั้งปีงบ ถ้ายังไม่มีอีกก็ค้างที่
    "ไม่ระบุช่องทาง") — ทุกบรรทัดมีป้าย "เฉลี่ยมา X%" กำกับ
  - **Invariant:** Σ ทุกช่องทางของบรรทัดหนึ่งในเดือนหนึ่ง = ยอดบรรทัดเดียวกัน
    ของงบระดับบริษัทเสมอ (มีเทสคุม `test_sum_of_channels_ties_to_company`)
- **สาขาอ่านจากหัวเอกสาร ไม่ใช่จากบรรทัด** — `account.move.line.partner_id`
  ของ core คือ *commercial partner* (สาขาถูกยุบเป็นบริษัทแม่ตั้งแต่ตอนโพสต์)
  ชั้นสาขาจึงกางจาก `account.move.partner_id` และทำเฉพาะบัญชีรายได้
- **ไม่มีงบกระแสเงินสดในแท็บนี้** — เคยมีตอน v17.0.11.0.0 แต่ตัดออกตามที่
  ผู้ใช้สั่ง (2026-09-04) เพราะเงินสดแยกตามช่องทางไม่ได้ ตารางระดับบริษัทซ้ำ
  กับที่อื่นเปล่า ๆ · อยากดูรายเดือนให้ไปที่ Statements หรือ Compare BI
  โหมดรายเดือน (ใช้ `_waterfall_columns` ตัวเดียวกัน ตัวเลขจึงตรงกันเป๊ะ)
- **โหลดแยกจาก payload หลัก** — `get_channel_data` ถูกเรียกตอนเปิดแท็บครั้งแรก
  และตอนเปลี่ยนมิติ/ช่องทางเท่านั้น (`get_dashboard_data` ไม่มีคีย์ `channel`)
  เพราะงบรายเดือนทั้งปีงบใช้ ≤ 2 aggregate query ต่อคอลัมน์ ไม่ควรถ่วงการโหลด
  หน้าแรกของทุกคน
- คลิกชื่อช่องทางในตารางเทียบ = ดูงบของช่องทางนั้น · คลิกตัวเลขเจาะ
  `account.move.line` ของเดือนนั้น (แถวที่เป็นยอดเฉลี่ยคลิกไม่ได้ เพราะไม่มี
  เอกสารต้นทาง)

## Controlling — ศูนย์ต้นทุนแบบ SAP CO (v17.0.3.0.0)

เลือกมิติได้จาก Analytic Plan ระดับรากทุกแผนในระบบ (Projects / Departments /
Business Unit ฯลฯ) แล้วดูต่อศูนย์ต้นทุน:

| คอลัมน์ | มาจาก |
|---|---|
| Budget | `crossovered.budget.lines` (om_account_budget) เฉพาะงบที่อนุมัติแล้ว (confirm/validate/done) เฉลี่ยตามจำนวนวันที่ทับช่วงปีงบ ใช้ `abs(planned_amount)` เหมือน biz_dashboard_finance |
| Actual Cost | `account.analytic.line` ฝั่งยอดติดลบ กลับเครื่องหมายให้อ่านเป็นบวก |
| Commitment | PO ที่ยืนยันแล้วยังไม่ตั้งบิล กระจายตาม `analytic_distribution` (รองรับคีย์หลายแผนคั่นด้วยคอมมา — แต่ละแผนได้ % เต็ม ไม่หาร) |
| Available | Budget − Actual Cost − Commitment |

กดเลขได้ทุกช่อง: ชื่อศูนย์/ใช้จริง → รายการวิเคราะห์, ภาระผูกพัน → PO,
งบประมาณ → บรรทัดงบ  โมดูลไม่ผูก `om_account_budget` เป็น dependency —
ถ้าไม่ได้ติดตั้ง คอลัมน์งบจะเป็น 0 และปุ่มเจาะงบจะถูกซ่อน

**Statements — งบการเงินแบบ SAP F.01 (v17.0.2.2.0):**

- **Balance Sheet** — ยอดสะสม ณ เดือนที่เลือก เทียบวันเดียวกันปีก่อน จัดกลุ่มตาม
  ประเภทบัญชี (เงินสด/ลูกหนี้/สินทรัพย์ถาวร/เจ้าหนี้/เงินกู้/ทุน) กดชื่อกลุ่มเพื่อ
  กาง-หุบรายบัญชี กดตัวเลขเพื่อเปิด journal items จริง; งบดุลเสมอเพราะส่วนของ
  ผู้ถือหุ้นรวมแถว "กำไรสะสมระหว่างปี" (P&L ที่ยังไม่ปิดงวด) — ถ้ามีบัญชี
  off-balance จะขึ้นป้ายเตือน "งบไม่ดุล" พร้อมส่วนต่าง
- **P&L Statement** — YTD เทียบงวดเดียวกันปีก่อน รายบัญชี + บรรทัดกำไรขั้นต้น /
  EBITDA / กำไรสุทธิ (% ของรายได้) พร้อม Δ และ Δ%
- **Cash Flow Statement (ทางอ้อม)** — สามกิจกรรม: ดำเนินงาน (กำไรสุทธิ + ค่าเสื่อม
  ± การเปลี่ยนแปลงเงินทุนหมุนเวียน) / ลงทุน / จัดหาเงิน กระทบยอดเงินสดต้นงวด→
  ปลายงวดได้พอดี (identity ปิดที่บัญชีประเภท asset_cash)
- **AR Aging** — ถังอายุลูกหนี้ 4 ถัง (แบบเดียวกับ AP) + ตารางรายลูกค้า
  Current / 1-30 / 31-60 / >60 กดลงใบแจ้งหนี้ค้างรับรายลูกค้าได้

**Drill-down ทุกตัวเลขสำคัญ (v17.0.2.1.0):** ตัวเลขที่มีขีดจุดใต้ = กดเจาะดู
เอกสารจริงได้ — KPI (ใบแจ้งหนี้/รายการบัญชี), เซลล์รายสัปดาห์ของ Cash Flow
Summary และ Supplier Payment Calendar (ใบครบกำหนดสัปดาห์นั้น), funnel ทุกขั้น,
ถัง AP Aging / Committed PO, เซลล์ heatmap ความเสี่ยง ฯลฯ โดเมนประกอบจาก
ตัวกรองที่ engine ยืนยันแล้วเท่านั้น และ record rule ของผู้ใช้ยังคุมทุกรายการ

## AI (v17.0.2.0.0)

ตั้งค่า **Settings ▸ Smart Finance** (OpenRouter API Key + model — key แยกของ
โมดูลนี้ ไม่ใช้ร่วมกับโมดูลอื่น) แล้วได้ 4 ความสามารถ:

1. **AI CFO Brief** — ปุ่ม "AI วิเคราะห์แท็บนี้" บนทุกแท็บ: สรุป + insights +
   action chips ภาษาไทยจากตัวเลขที่เห็นจริง
2. **CFO Copilot** (แท็บ AI Copilot) — แชทถาม-ตอบข้อมูลการเงิน บทสนทนา
   เก็บใน DB เห็นเฉพาะของตัวเอง
3. **AI เสนอความเสี่ยง** (manager) — สร้าง draft "[AI] ..." เข้า Risk Register
   พร้อม impact/likelihood/early warning (dedupe อัตโนมัติ ให้คนรับ/แก้/ทิ้ง)
4. **รายงาน CFO ประจำเดือน** — markdown commentary เก็บเป็น record
   (เมนู Smart Finance ▸ รายงาน AI)

กติกาความปลอดภัยของข้อมูล: client ส่งได้แค่ชื่อแท็บ + filters — **ตัวเลขทั้งหมด
engine ดึงเองฝั่ง server** (ผ่าน gate สิทธิ์เดียวกับ dashboard) และถูกบีบเหลือ
ตารางละ ≤8 แถวก่อนส่งโมเดล; system prompt ห้ามโมเดลแต่งตัวเลขเอง

## Inventory & Financial Ratios — เลือกแหล่งข้อมูลต่อบริษัท (v17.0.4.0.0)

ตั้งที่ **Configuration ▸ Settings** ของแต่ละบริษัท: `แหล่งข้อมูลสินค้าคงเหลือ`
และ `แหล่งข้อมูลอัตราส่วนการเงิน` = **Odoo** หรือ **ระบบภายนอก** (จอแสดง badge
บอกที่มาเสมอ; กลุ่มที่ปนกันขึ้นว่า "ผสม")

ข้อมูลจากระบบภายนอกเข้ามาได้ 3 ทาง แต่ลงตารางเดียวกัน
(`biz.smart.finance.ext.fact`) แล้วแดชบอร์ดอ่านทางเดียว:

1. **กรอกมือ** — ข้อมูลนำเข้า ▸ External Figures
2. **นำเข้าไฟล์** — ข้อมูลนำเข้า ▸ Import External Figures (CSV / XLSX
   คอลัมน์ `kind, metric_key, category, amount, qty`; upload → preview → import)
3. **API** — ตั้ง endpoint/API key ที่ Settings ▸ Smart Finance ▸ External Source
   และรหัสบริษัทภายนอกที่ Smart Finance Settings แล้วกดปุ่ม Sync (หรือเปิด cron
   `Smart Finance: sync external figures` ซึ่งปิดไว้เป็นค่าตั้งต้น)
   รูปแบบ JSON ที่คาดหวังอยู่ใน docstring ของ `models/bsf_source_service.py`

กติกาที่ต้องรู้เวลาอ่านตัวเลข:

- **สต๊อกมีสองฐานวัด** — Quick Ratio หักสต๊อกจาก **ยอด GL** ของบัญชีที่ map ไว้
  (ไม่ map = Quick เท่ากับ Current พร้อมหมายเหตุ) ส่วน Turnover/DIO ใช้
  **stock valuation (SVL)** ซึ่งเป็นฐานการเคลื่อนไหว ส่วนต่างสองฐานแสดงเป็น
  badge "กระทบยอด SVL ↔ GL" ในแท็บ Inventory ไม่ใช่ซ่อนไว้
- อัตราส่วนที่ **ตัวหารเป็นศูนย์หรือติดลบ** (หนี้สินหมุนเวียน/ส่วนของผู้ถือหุ้น/
  รายได้ติดลบ) แสดง "—" ไม่ใช่ตัวเลข เพราะเครื่องหมายจะพลิกจนอ่านว่าแข็งแรง
- กลุ่มหลายบริษัทรวม **ตัวตั้ง** ก่อนแล้วค่อยหาร (ratio ของผลรวม)
- Cash Conversion Cycle รวม DIO แล้ว = DSO + DIO − DPO

## ใบแจ้งหนี้ (AR/AP) & งบศูนย์ต้นทุน — เลือกแหล่งข้อมูลต่อบริษัท (v17.0.5.1.0)

สำหรับบริษัทที่**ไม่ได้ออกเอกสารหรือตั้งงบใน Odoo** ตั้งที่ **Configuration ▸
Settings** ของบริษัทนั้น: `แหล่งข้อมูลใบแจ้งหนี้/บิลค้าง` และ
`แหล่งข้อมูลงบศูนย์ต้นทุน` = **Odoo** หรือ **ระบบภายนอก**

| ตั้งเป็น "ระบบภายนอก" แล้ว | ตารางที่ระบบอ่าน | มีผลกับ |
|---|---|---|
| ใบแจ้งหนี้/บิลค้าง | `biz.smart.finance.ext.invoice` | AR aging (Statements), AP & Payment Plan, 13-week Cash Forecast, Forecast รายเดือน, กรวย Sales to Cash / DSO |
| งบศูนย์ต้นทุน | `biz.smart.finance.ext.budget` | คอลัมน์ Budget / Available / Utilization ในแท็บ Controlling |

เข้าได้ 3 ทางเหมือน External Figures — กรอกมือ (ข้อมูลนำเข้า ▸ External
Invoices / External Budgets), นำเข้าไฟล์ (ข้อมูลนำเข้า ▸ Import Invoices /
Budgets), หรือ API sync (คีย์ `invoices` / `budgets` ใน JSON ชุดเดียวกับ
`inventory`/`metrics` — ดู docstring ของ `models/bsf_source_service.py`)

กติกาที่ต้องรู้:

- บริษัทที่ตั้งเป็น **ระบบภายนอก จะไม่อ่านบรรทัด AR/AP ใน GL เลย** (ไม่ใช่เอามา
  บวกกัน) — กันยอดซ้ำ; กลุ่มที่ปนกันหลายบริษัททำงานได้ จอขึ้นว่า "ผสม"
- ยอดในตารางภายนอกเป็น**บวกทั้งสองฝั่ง** (ยอดที่ยังไม่ได้รับ / ยังไม่ได้จ่าย)
  สกุลเงินของบริษัทนั้น ใบลดหนี้ใส่ติดลบทั้งยอดรวมและยอดค้าง
- ไม่ใส่วันครบกำหนด = ถือว่าครบกำหนดวันที่เอกสาร (ตกถังเกินกำหนดทันที)
- คู่ค้าที่**ผูก `res.partner`** ไว้ จะคลิกจากตาราง Top Customer/Supplier เข้าไป
  ดูเอกสารใน Odoo ต่อได้ ถ้าไม่ผูกยังจัดกลุ่มตามชื่อให้ แต่คลิกต่อไม่ได้
- งบภายนอก**ต้องผูก analytic account จริง** (รหัสหรือชื่อ) เพราะต้นทุนจริงกับ
  ภาระผูกพันยังมาจาก analytic line/PO ของ Odoo — resolve ไม่ได้ = ไฟล์ถูกบล็อก
  และ API รายงาน error ไม่เดาให้
- งบเฉลี่ยตามจำนวนวันที่ทับช่วงงวดที่ดูอยู่ (pro-rata) เหมือนงบของ Odoo

## หน้าจอกรอกข้อมูล (เมนู Smart Finance)

- **Configuration ▸ Settings** — ต่อบริษัท: เงินสดขั้นต่ำ, เป้า D/E, เป้า DSO,
  เพดาน leakage, ตัวคูณ scenario, mapping บัญชีค่าเสื่อม/ดอกเบี้ย/ภาษี/เงินกู้
- **ข้อมูลนำเข้า ▸ Cash Flow Lines** — เงินเดือน/ค่าเช่า/ภาษี รายสัปดาห์-รายเดือน-ครั้งเดียว
- **ข้อมูลนำเข้า ▸ งานขาย (Pipeline)** — ดีลก่อนเซ็นสัญญา: มูลค่า, ความน่าจะเป็น,
  วันที่คาดว่าจะเซ็น, ระยะเวลางาน, แบบแผนวางบิล, กำไรขั้นต้นที่คาด
- **ข้อมูลนำเข้า ▸ แบบแผนวางบิล** — กี่ % ที่เดือนไหนนับจากเดือนที่เซ็น (รวม 100)
- **ข้อมูลนำเข้า ▸ ภาพนิ่งพยากรณ์** — อ่านอย่างเดียว, cron เก็บให้ทุกต้นเดือน
- **ข้อมูลนำเข้า ▸ Risk Register** — ความเสี่ยง impact × likelihood
- **ข้อมูลนำเข้า ▸ Variation Orders** — งานเพิ่ม/ลด + ผลต่อ margin
- **ข้อมูลนำเข้า ▸ External Figures / Import External Figures** — มูลค่าสินค้า
  คงเหลือรายหมวด และตัวเลขงบการเงินจากระบบภายนอก
- **ข้อมูลนำเข้า ▸ External Invoices** — ใบแจ้งหนี้ค้างรับ/บิลค้างจ่ายจากระบบภายนอก
- **ข้อมูลนำเข้า ▸ External Budgets** — งบต้นทุนต่อศูนย์ต้นทุนและช่วงวันที่
- **ข้อมูลนำเข้า ▸ Import Invoices / Budgets** — นำเข้าสองตารางข้างบนจาก CSV/XLSX

Dashboard จะขึ้นแถบเตือนพร้อมลิงก์เมื่อยังไม่ได้กรอกข้อมูลส่วนไหน

## ข้อจำกัด v1 (ตั้งใจ)

- EBITDA แม่นเมื่อ map บัญชีดอกเบี้ย/ภาษีแล้ว — ก่อนหน้านั้น = กำไรสุทธิ + ค่าเสื่อม
- กันนับซ้ำใน cash forecast ด้วยกติกา: แผนบิล/แผนจ่ายนับเฉพาะงวดที่ยังไม่ตั้งบิล
  (งวดที่ตั้งบิลแล้วนับผ่าน AR/AP คงค้างแทน), PO นับเฉพาะส่วนที่ยังไม่ตั้งบิล
- Funnel ฐานต่างชนิด (order intake vs earned value) — conversion % เป็นทิศทาง
- Inventory: แนวโน้มรายงวดใช้ยอดสะสมของ SVL ต่อวันสิ้นงวด (ถ้าไม่มีโมดูล Stock
  จะเหลือยอด GL อย่างเดียว ไม่มีรายหมวด/รายสินค้า/แนวโน้ม) และ drill-down
  รายสินค้าเป็นตารางในจอ ไม่ลิงก์ไป `stock.valuation.layer` เพราะ ACL ของ core
  จำกัดที่ stock manager
- ตัวเลขภายนอกถือเป็น**สกุลเงินของบริษัทนั้น** adapter ไม่แปลงค่าให้เอง
  (สกุลไม่ตรงจะรายงาน error ไม่เขียนลงตาราง) และ ratio ประสิทธิภาพใช้ metric
  `*_t12m` ถ้ามี ไม่งั้น annualize จาก YTD (ต้นปีงบจึงหยาบ)
- Statements: aging นับจาก "วันนี้" (ไม่ใช่ as-of ที่เลือก — เท่ากติกา AP),
  Cash Flow จัดกิจกรรมตาม account_type ล้วน (เงินกู้ระยะสั้นจะตกใน "หนี้สิน
  หมุนเวียนอื่น" ฝั่งดำเนินงาน)
- **การแปลงค่าเงินใช้ closing rate ทั้งงบ ไม่ใช่ average rate กับ P&L** —
  จึงไม่มีบรรทัด "ผลต่างจากการแปลงค่างบการเงิน (CTA)" แยกออกมา เป็นการแลก
  ความละเอียดกับความสอดคล้องภายในที่ตรวจสอบได้ (ถ้าใช้สองอัตราในงบชุดเดียว
  งบดุลจะไม่ดุลและต้องมี CTA มาอุด ซึ่งเทสจับความผิดพลาดจริงไม่ได้อีกต่อไป)
  งบกระแสเงินสดจึงไม่แยกผลกระทบอัตราแลกเปลี่ยนเป็นบรรทัดต่างหากด้วย
- Controlling: `crossovered.budget.lines.practical_amount` ของ om เป็น
  compute แบบ N+1 raw SQL ที่ไม่กรองบริษัทและนับ draft ด้วย — engine นี้
  **ไม่ใช้** ค่านั้น แต่รวม actual เองจาก `account.analytic.line`
- Controlling แสดงสูงสุด 25 ศูนย์ต้นทุนต่อมิติ (payload บอก `row_count`
  ทั้งหมดไว้ให้เทียบ)
- Forecast: รับรู้รายได้/ต้นทุนเกลี่ยเป็น**เส้นตรงตามวัน** ในช่วงแผนงาน
  (ไม่มี S-curve) และรายการประจำที่ไม่มีวันสิ้นสุดไม่ลงคอลัมน์ "หลังจากนี้"
  (จ่ายตลอดไป = ไม่มีภาระที่ระบุวันได้) ส่วน scenario เลื่อนเฉพาะ**เงินเข้า**
  1 เดือน (Downside) / 2 เดือน (Stress) ไม่แตะจังหวะเงินออก
- Forecast: งบ BOQ ที่ยังไม่มี PO หักยอดแผนจ่ายผู้รับเหมาออกทั้งโครงการ
  (ตัดที่ 0 ไม่ให้ติดลบ) เพราะแผนจ่ายบางงวดไม่มี PO ผูกกลับมาที่บรรทัด BOQ
  — เป็นการประมาณระดับโครงการ ไม่ใช่ระดับบรรทัด
- Compare (BI) เป็นระดับสรุป (ไม่มีแถวรายบัญชีแบบ Statements) — ทั้งบนจอและใน
  ไฟล์ส่งออก ถ้าต้องการรายบัญชีให้ใช้แท็บ Statements ซึ่งเทียบได้ทีละสองงวด
- PDF เป็น A4 แนวตั้ง ตารางเปรียบเทียบ 6 ช่วง (7 คอลัมน์) จึงย่อฟอนต์ลงเหลือ
  8.5px เฉพาะตารางนั้น (`.bsf-cmp`) — เพิ่มช่วงเกินนี้ต้องเปลี่ยนเป็นแนวนอน

## กรอกมือและนำเข้า CSV / Excel

รองรับข้อมูลภายนอก 4 กลุ่ม: External Invoices (AR/AP), External Budgets,
External Figures และ Trial Balance ภายนอก เข้าแต่ละหน้าจาก **ข้อมูลนำเข้า**
แล้วกรอกในตารางได้เลย หรือกด **นำเข้าไฟล์ CSV / Excel** บนหน้ารายการ
(สิทธิ์ CFO Cockpit / Manager) ระบบเลือกชนิดข้อมูลให้ตรงกับหน้าที่เปิด
External Figures เปิดฟอร์มรายละเอียดได้ด้วย

1. เลือกบริษัท และระบุวันสิ้นงวด/ช่วงวันที่สำหรับ Figures หรือ Trial Balance
2. ดาวน์โหลด **ตัวอย่าง CSV** หรือ **Excel พร้อมคำแนะนำ** แล้วแทนข้อมูลตัวอย่างด้วยข้อมูลจริง
   Excel มีคำอธิบายหัวคอลัมน์และตัวเลือกรหัสในแผ่น `คำแนะนำ`; แผ่น `ข้อมูล` เป็นแผ่นที่อ่าน
   งบประมาณใช้รหัสศูนย์ต้นทุนที่มีอยู่จริง หากยังไม่มีต้องสร้างศูนย์ต้นทุนก่อน
3. อัปโหลดแล้วกด **ตรวจไฟล์** ข้อผิดพลาดแสดงข้างแถว และยังเก็บค่าจากช่องอื่นที่อ่านได้
4. แก้ เพิ่ม หรือลบแถวใน Preview แล้วกด **ตรวจสอบข้อมูล** เพื่อตรวจตารางปัจจุบัน
   ปุ่มนี้ไม่อ่านไฟล์ต้นฉบับซ้ำ ยอดสรุปและจำนวนแถวปรับตามข้อมูลที่แก้
   หากแก้ค่าที่อ่านไม่ได้เป็น `0` ให้บันทึกแถวนั้น/กดตรวจสอบข้อมูลเพื่อยืนยันการแก้
5. กด **นำเข้า** เมื่อข้อมูลถูกต้อง ระบบตรวจใหม่ก่อนเขียนเสมอ ถ้าพบแถวผิดจะไม่เขียนทั้งชุด
   Trial Balance เข้าสถานะร่าง ตรวจยอดแล้วกดยืนยันอีกครั้ง

เปลี่ยนไฟล์หรือชนิดข้อมูลจะล้าง Preview เดิม; เปลี่ยนบริษัท/งวดจะตรวจตารางเดิมใหม่
คู่ค้าและศูนย์ต้นทุนต้องอยู่ในบริษัทที่เลือกหรือเป็นรายการใช้ร่วมกัน
ชื่อคู่ค้าที่จับคู่ไม่ได้ยังเก็บเป็นชื่อจากไฟล์ โดยไม่สร้างคู่ค้าใหม่อัตโนมัติ
พฤติกรรมแทนที่รายการซ้ำยังเหมือนเดิม (TB แทนที่ทั้งงวดและกลับเป็นร่าง)

**รูปแบบไฟล์:** CSV เป็น UTF-8; วันที่เป็น `YYYY-MM-DD` ปี ค.ศ. หรือเซลล์วันที่จริงของ Excel;
ยอดเงินเป็นสกุลเงินบริษัท; รหัสบัญชี/เลขที่เอกสารที่มีศูนย์นำหน้าให้เก็บเป็นข้อความ
ใช้ค่าข้อมูลแทนสูตร Excel หัวคอลัมน์ต้องไม่ซ้ำและไม่มีข้อมูลเกินหัวคอลัมน์
NaN/Infinity ไม่ใช่ยอดเงินที่นำเข้าได้ ช่องจำนวนที่เว้นว่างยังใช้ค่าเริ่มต้นเดิม (`0`)

**ติดตั้ง:** ติดตั้ง `pip3 install -r /mnt/extra-addons/biz_smart_finance/requirements.txt`
ใน Python environment ของ Odoo ก่อนอัปเกรดโมดูล และเพิ่มคำสั่งนี้ในขั้นตอน build image
เพื่อให้มี `openpyxl` สำหรับอ่าน XLSX และ `xlsxwriter` สำหรับสร้างตัวอย่าง Excel หลังสร้าง container ใหม่
จากนั้นอัปเกรด `biz_smart_finance` บนฐานที่ต้องการใช้งาน

## กลยุทธ์ CFO, Cost Control และ Break-even (17.0.12.0.0)

เพิ่มแท็บ **กลยุทธ์และ Action** และ **ต้นทุนและจุดคุ้มทุน** ซึ่งโหลดข้อมูลเมื่อเปิดแท็บ
ใช้กฎและแม่แบบ ไม่เรียก AI และไม่เขียนกลับบัญชี/ใบแจ้งหนี้/แผนจ่าย/Forecast ใช้งานจริง

### เริ่มใช้งาน

1. กำหนดกลุ่ม `CFO Cockpit / Manager`, Viewer และ **ผู้รับ Action** ให้เหมาะสม
   ผู้รับ Action มีเมนู **งาน CFO ของฉัน** แยก และอ่านเฉพาะงานที่ได้รับ
   ไม่ได้รับสิทธิ์ CFO Dashboard หรือข้อมูลเงินเดือนทั้งบริษัทโดยอัตโนมัติ
2. สร้างทะเบียนฝ่ายที่ **กลยุทธ์และควบคุมต้นทุน → ฝ่ายวิเคราะห์ต้นทุน**
   ทำเครื่องหมายฝ่ายที่มียอดขายเฉพาะฝ่ายที่สามารถจัดสรรรายได้และต้นทุนครบได้
3. สร้าง **ข้อมูลต้นทุนรายเดือน** (วันที่ 1 ของเดือน สกุลเงินบริษัท)
   กรอกแถวเองหรือกดนำเข้า CSV/XLSX และดาวน์โหลดแม่แบบ
   นำเข้าแล้วเป็นร่าง ตรวจข้อมูลและทำเครื่องหมายครบถ้วนก่อนยืนยัน
4. ตั้งเกณฑ์ต้นทุนใน Configuration: บุคลากร/ยอดขาย, OT/บุคลากร,
   ส่วนต่างการเติบโตค่าใช้จ่ายกับยอดขาย, อัตรากำไรส่วนเกินลด, DIO และกำไรช่องทาง
   ค่า 0 หมายถึงยังไม่ตั้งเกณฑ์ ไม่ใช่การผิดเกณฑ์โดยอัตโนมัติ
5. สร้างกลยุทธ์รายปี KPI รายไตรมาส และบันทึกทบทวนรายเดือน
   จากแท็บกลยุทธ์กด **ประเมินปัญหาและสร้างประเด็น** แล้วเปิดหลักฐาน
   ยืนยันสาเหตุและสร้าง/เปิด Action ที่เกี่ยวข้อง
6. เลือกข้อมูลที่จะเปิดให้ผู้รับงาน เจ้าของงาน และกำหนดเสร็จ ก่อนส่งอนุมัติ
   ผู้รับงานเริ่มงาน อัปเดตผล และส่งหลักฐาน ฝ่ายการเงินตรวจรับก่อนปิดงาน

### รูปแบบต้นทุนและข้อมูลนำเข้า

หัวคอลัมน์: `source_key,name,department,category,amount,fixed_pct,one_off,allocation_complete`

- `source_key`: รหัสไม่ซ้ำต่อชุดข้อมูล นำเข้ารหัสเดิมซ้ำจะอัปเดตแถวนั้นในชุดร่าง
  ไม่ลบแถวอื่น ไม่สร้างยอดซ้ำ ตรวจไฟล์และแก้แถวตัวอย่างก่อนนำเข้าได้
- `department`: ชื่อฝ่ายตรงทะเบียนบริษัท ว่างคือยังไม่จัดสรร/ส่วนกลาง
  ใส่ต้นทุนระดับฝ่ายรวมส่วนกลางเท่านั้น **ไม่กรอกยอดรวมบริษัทซ้ำอีกแถว**
- `category`: `sales`, `salary`, `ot`, `benefits`, `employer`, `subcontract`,
  `material`, `rent`, `utilities`, `transport`, `marketing`, `software`,
  `depreciation`, `interest`, `tax`, `other`
- `amount`: จำนวนเงินไม่ติดลบ ยอดขายคือยอดขายสุทธิประจำเดือน
- `fixed_pct`: 0–100; 0 คือผันแปรทั้งหมด 100 คือคงที่ทั้งหมด
- `one_off`: 1/0 หรือ true/false สำหรับค่าใช้จ่ายครั้งเดียว
- `allocation_complete`: 1/0 ยืนยันจัดสรรต้นทุนครบสำหรับจุดคุ้มทุนรายฝ่าย
- จำนวนคนเฉลี่ยและ FTE กรอกแยกในแท็บกำลังคน ไม่เก็บเงินเดือนรายบุคคล
  ผลิตภาพต่อ FTE จะแสดงเมื่อข้อมูลกำลังคนครอบคลุมฝ่ายที่มีต้นทุน

ฉบับยืนยันและรายละเอียดแก้ไขหรือลบไม่ได้ ให้กด **สร้างฉบับแก้ไข**
ฉบับเก่ายังคงใช้งานจนฉบับใหม่ยืนยัน แล้วเก็บฉบับเก่าเป็นประวัติ
บริษัทหนึ่งมีฉบับยืนยันปัจจุบันได้หนึ่งชุดต่อเดือน

### สูตรและข้อจำกัดของข้อมูล

กำไรส่วนเกิน = ยอดขาย − ต้นทุนผันแปร
อัตรากำไรส่วนเกิน = กำไรส่วนเกิน / ยอดขาย
ยอดขายคุ้มทุน = (ต้นทุนคงที่ + ค่าใช้จ่ายครั้งเดียว) / อัตรากำไรส่วนเกิน
ยอดขายเพื่อกำไรเป้า = (ต้นทุนคงที่ + ค่าใช้จ่ายครั้งเดียว + กำไรเป้า) / อัตรากำไรส่วนเกิน

แสดงผลก่อนค่าใช้จ่ายครั้งเดียวแยก รวมค่าเสื่อมในต้นทุนดำเนินงาน แต่แยกดอกเบี้ยและภาษีเงินได้
ยอดขายศูนย์ กำไรส่วนเกินไม่เป็นบวก หรือข้อมูลไม่ครบ แสดงเหตุผลและไม่แสดงจุดคุ้มทุนเทียม
ต้นทุนฝ่ายสนับสนุนแสดงได้ แต่ไม่คำนวณจุดคุ้มทุนโดยไม่มีฐานรายได้/การจัดสรรครบ
การเทียบบัญชีใช้ยอดขายดำเนินงานและค่าใช้จ่ายรวม; TB ภายนอกต้องยืนยันและตรงเดือน
ไม่ใช้รายการแผนเงินสดเงินเดือนเป็นค่าใช้จ่ายจริงซ้ำ

ข้อมูลสรุปเป็น **เต็มเดือน**; ไม่กระจายยอดรายเดือนเป็นรายวันเพื่อให้ดูเหมือนยอด ณ วันกลางเดือน
แต่ละบริษัทใช้สกุลเงินและปีงบของตัวเอง ไม่รวมจำนวนเงินต่างสกุลเข้าด้วยกัน
ข้อมูลต้นทุนนี้ยังเป็นการนำเข้าสรุปโดยการเงิน ไม่ได้เชื่อม Payroll หรือจัดประเภทบัญชีอัตโนมัติ

### จำลองและตรวจรับผล

สร้างทางเลือกเพิ่มยอดขาย ลดต้นทุน หรือผสม → **เก็บฐาน** → ปรับสมมติฐาน → **จำลองผล**
ฐานประกอบด้วยชุดต้นทุนที่ยืนยันและภาพ Forecast สด ณ เวลาบันทึก
หากชุดต้นทุนถูกแทนที่หรือ Forecast เปลี่ยน ระบบแจ้งฐานเปลี่ยน ให้ทำสำเนาและเก็บฐานใหม่
การเก็บฐานจะตั้งยอดขายและอัตราต้นทุนเริ่มต้นให้ จึงควรปรับสมมติฐานหลังเก็บฐาน

- จำลอง run-rate รายเดือนคงที่ 1–18 เดือนจากเดือนเริ่มผล
  ไม่ทำซ้ำค่าใช้จ่ายครั้งเดียวในอดีต หักค่าใช้จ่ายเปลี่ยนแผนในเดือนแรก
- ลดต้นทุนคงที่ต้องอ้างแถวฐาน ผลลดรวมต่อแถวเกินส่วนคงที่ไม่ได้
  Action ที่มีรหัสกลุ่มทางเลือกเดียวกันเลือกใช้ร่วมกันไม่ได้
- เงินสดเป็น **ส่วนต่างจากฐาน** พร้อมเดือนรับ/จ่าย ไม่แปลงผลกำไรเป็นเงินสดอัตโนมัติ
  ยืนยันจังหวะรวมค่าใช้จ่ายดำเนินแผนก่อนคำนวณ การเลื่อนเงินให้กรอกสองขา
  และใช้ `shift_key` เดียวกัน ระบบตรวจยอดรวมของกลุ่มเป็นศูนย์
  เงินเกินช่วง Forecast อยู่คอลัมน์หลังจากนี้
- การตรวจรับต้นทุนใช้ flexible budget:
  `ต้นทุนผันแปรฐาน / ยอดขายฐาน × ยอดขายจริง − ต้นทุนผันแปรจริง + ต้นทุนคงที่ฐาน − ต้นทุนคงที่จริง − ค่าใช้จ่ายครั้งเดียวจริง`
  ผู้ตรวจจัดสรรผลให้แต่ละ Action พร้อมหลักฐาน ไม่ถือว่าต้นทุนลดทั้งหมดเกิดจาก Action เดียว
  ยอดตรวจรับรวมของเดือนเดียวกันห้ามเกินผลที่ปรับกิจกรรม และต้องใช้ฐาน/ฉบับผลจริงเดียวกัน
- งาน KPI ที่ไม่ใช่ผลประหยัดต้นทุนตรวจรับด้วยหลักฐานและผลประหยัด 0 ได้
  เงินประหยัดคาดการณ์ ผลต่างค่าใช้จ่ายจริง และผลตรวจรับ แสดงแยกกัน
- งานอนุมัติที่แก้แผน/เป้าหมายจะกลับรออนุมัติใหม่ การตรวจรับแล้วแก้หรือลบไม่ได้
  cron รายวันสร้าง Activity ติดตามงานเกินกำหนดให้ Manager โดยไม่สร้าง Activity เปิดซ้ำ

### ตรวจสอบก่อนขึ้นระบบ

อัปเกรด `biz_smart_finance` บนฐานทดสอบแยกก่อน และรัน
`--test-enable --test-tags /biz_smart_finance --stop-after-init --max-cron-threads=0`
โดยกำหนดพอร์ต HTTP ทดสอบที่ไม่ชนระบบเดิมและปิดการส่งอีเมลของฐานสำเนา
ไม่มี migration ที่เขียนทับ Risk หรือข้อมูลเดิม และไม่ต้องสร้างข้อมูลต้นทุนย้อนหลังเพื่ออัปเกรด

ชุด `TestBsfStrategy` ครอบคลุมสูตรคุ้มทุน 12.5 ล้าน/เป้ากำไร 15 ล้าน,
ต้นทุนผสม OT ดอกเบี้ย/ภาษี, ฉบับแก้ไขและการห้ามแก้ผ่าน context/RPC,
นำเข้า CSV/XLSX ซ้ำ, สิทธิ์เจ้าของงานและหลายบริษัท, การอนุมัติ/ตรวจรับ,
ผลลดซ้ำและทางเลือกขัดกัน, เงินสดข้ามช่วงและฐานเปลี่ยน,
ผลประหยัดปรับกิจกรรม, การตรวจรับซ้ำ และการประเมิน/เตือนซ้ำ

ฐานเงินสดจำลองแปลงจากสกุลรายงาน Dashboard เป็นสกุลบริษัทก่อนใช้ส่วนต่างเงินสด
เก็บสกุลต้นทาง อัตรา และวันที่แปลงไว้ในภาพฐาน; เก็บต้นฉบับ Forecast ไว้ตรวจสอบด้วย
ผลตรวจรับผูกกับฉบับแผน การเปิดทบทวนหรือแก้แผนหลังอนุมัติต้องตรวจรับฉบับใหม่ก่อนปิดงาน
