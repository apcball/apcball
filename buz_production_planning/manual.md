# คู่มือการใช้งาน BUZ Production Planning

โมดูลวางแผนการผลิตสำหรับ Odoo 17 ของ Mogen Co. ทำ flow ตั้งแต่ความต้องการสินค้า (ใบส่งของค้าง + ค่าพยากรณ์ + สต็อกสำรอง) → คำนวณความต้องการสุทธิแบบหลายชั้น BoM → เสนอ **ผลิต/ซื้อ** → สร้าง **MO แบบร่าง** และ **Blanket Order (หรือ RFQ) แบบร่าง** → จัดคิว workorder ลง workcenter → ดูและลากแก้บน **Gantt** → **Apply** วันที่ลง workorder จริง

> ชื่อเมนูและปุ่มเป็นภาษาอังกฤษ (มีคำแปลไทยเมื่อเลือกภาษาไทย) คู่มือนี้ใช้ชื่อตามหน้าจอภาษาอังกฤษ

## 1. ภาพรวมและแนวคิดสำคัญ

### โครงสร้างเมนู (Planning)

| เมนู | ใช้ทำอะไร |
|---|---|
| **Dashboard** | หน้าแรกของเมนู Planning สรุปงานที่รอทำและภาระงานของแผนที่เลือก (ดูอย่างเดียว) |
| **Plans** | หัวแผน สร้าง/คำนวณ/จัดคิว/Apply หน้าแผนมีแถบสีฟ้า "ขั้นตอนถัดไป" บอกว่าต้องทำอะไรต่อ |
| **Suggestions** | ข้อเสนอผลิต/ซื้อ อนุมัติหรือปฏิเสธ |
| **Demand** | ความต้องการรายสินค้ารายสัปดาห์ (แก้ค่าพยากรณ์ได้) |
| **Schedule** | คิวงานที่เสนอ (ตาราง + pivot) |
| **Gantt** | แผนภูมิ Gantt ต่อ workcenter ลากย้าย/ยืดหดได้ |
| **Load vs Capacity** | ภาระงานเทียบกำลังการผลิต |
| **Configuration → Product Parameters** | พารามิเตอร์วางแผนต่อสินค้า |
| **Configuration → Operation Time History** | เวลาจริงเทียบเวลามาตรฐานของแต่ละ operation |
| **Configuration → Settings** | ค่าตั้งต้นของโมดูล (เฉพาะ Manager) |

### แนวคิดสำคัญ

- **โมดูลนี้ไม่แตะสต็อก** ไม่ confirm MO/PO ไม่ reserve ไม่เบิกของ เอกสารที่สร้างมีแค่ **MO สถานะ Draft** และ **Blanket Order สถานะ Draft** (หรือ **RFQ สถานะ Draft** ถ้าเลือก) การเบิกวัตถุดิบยังเป็นหน้าที่ของ flow เดิม (`buz_mrp_stock_request`)
- **Demand ที่เชื่อได้** = ใบส่งของ (delivery) ที่ยังเปิดอยู่และปลายทางเป็นลูกค้า ไม่ใช้บรรทัดค้างส่งของ Sales Order
- **ข้อมูลก่อน 2026-04-01 ไม่ใช้** (วัน cut-off ตั้งได้ใน Settings)
- **Bucket = สัปดาห์** (จันทร์–อาทิตย์) ของที่ค้างเกินกำหนดลงสัปดาห์แรก ของที่เลยปลาย horizon ไม่นับ
- **Demand ต่อสัปดาห์ = max(ใบส่งของ, ค่าพยากรณ์)** ค่าพยากรณ์ไม่บวกซ้อนกับใบส่งของที่มีอยู่แล้ว
- **Supply** = สต็อกในคลังที่เลือก + PO เปิด + MO เปิด + เอกสารแบบร่างที่แผนสร้างไว้ (รวม **Blanket Order ที่แผนสร้างและยังเปิดอยู่** นับเท่าที่ยังไม่ได้ออก PO)
- ผลจัดคิวอยู่ในตาราง Schedule จนกว่าจะกด **Apply** ถึงจะเขียนลง workorder จริง

### Flow โดยย่อ

```
Plans → New → Compute Plan                        (ขั้นที่ 1)
      → Suggestions: ตรวจ / Approve / Reject
      → Create Documents (MO draft / Blanket Order draft หรือ RFQ draft)   (ขั้นที่ 2)
      → Schedule                                       (ขั้นที่ 3)
      → Gantt (ลากแก้) → Apply Schedule                (ขั้นที่ 4)
```

## 4. พารามิเตอร์สินค้า

เมนู **Configuration → Product Parameters** ใช้กำหนดวิธีวางแผนรายสินค้า สินค้าที่ไม่มีบรรทัดพารามิเตอร์จะใช้ค่าเริ่มต้น (วางแผนอัตโนมัติ ไม่มี safety stock)

| ฟิลด์ | ความหมาย |
|---|---|
| Product | สินค้า (ประเภท Storable) หนึ่งสินค้าต่อหนึ่งบรรทัดต่อบริษัท |
| Safety Stock | จำนวนขั้นต่ำที่ต้องมีเสมอ ต่ำกว่านี้ระบบเสนอผลิต/ซื้อ |
| Minimum Batch Qty | ปัดจำนวนเสนอขึ้นให้ไม่ต่ำกว่านี้ |
| Batch Multiple | ปัดจำนวนเสนอขึ้นเป็นจำนวนเท่าของค่านี้ |
| Manufacturing / Purchase Lead Time | วันที่ใช้ผลิต/วันที่รอของ (ว่าง = ใช้ค่าจาก BoM/vendor/Settings) |
| Supply Method | Automatic (มี BoM → ผลิต ไม่มี → ซื้อ) / Make / Buy / **Do not plan** (ไม่วางแผนสินค้านี้) |
| Production Line | สายผลิตของ MO ที่จะสร้าง |
| Vendor Override | บังคับใช้ vendor นี้แทน vendor หลัก |
| Forecast Method | Average of past deliveries / Manual / None |

### ปุ่ม Compute Defaults from History

เลือกบรรทัดแล้วกดปุ่ม ระบบเติมจากประวัติตั้งแต่วัน cut-off:

- lead time ผลิต = ค่ากลางของ (วันเสร็จ − วันเริ่ม) ของ MO ที่ done ถ้าต่ำกว่า 0.5 วัน ถือว่าไม่มีข้อมูล ใช้ค่า Settings
- lead time ซื้อ = ค่ากลางของวันจากอนุมัติ PO ถึงรับของ
- Production Line = ของ MO ล่าสุดของสินค้านั้น
- Minimum Batch Qty = ค่ากลางขนาด MO

> **สำคัญ:** BoM บน prod แทบทุกใบไม่ได้ระบุสายผลิต ระบบจึงใช้สายผลิตของ **MO ล่าสุด** ของสินค้าให้อัตโนมัติ สินค้าที่ไม่เคยมี MO และไม่มีพารามิเตอร์ จะไม่มีสายผลิต (ดูหัวข้อ 13)

## 5. สร้างแผนและคำนวณ

เมนู **Plans → New**

| ฟิลด์ | ความหมาย |
|---|---|
| Date From | วันเริ่มแผน (ใช้จันทร์ของสัปดาห์นี้เป็น bucket แรก) |
| Horizon Weeks | จำนวนสัปดาห์ |
| Supply Warehouses | คลังที่นับเป็นของพร้อมใช้ (เติมจาก Settings) |
| Production Lines | จำกัดเฉพาะสายผลิต (ว่าง = ทุกสาย) |
| Forecast Lookback Weeks | ย้อนดูยอดส่งกี่สัปดาห์ (ไม่ย้อนก่อนวัน cut-off) |

กด **Compute Plan** ระบบจะ:

1. รวมใบส่งของค้าง + ค่าพยากรณ์ (ค่าเฉลี่ยรายสัปดาห์) + วัตถุดิบที่ MO เปิดยังต้องใช้
2. หักสต็อก + ของที่กำลังจะเข้า (PO เปิด, MO เปิด, ข้อเสนอที่อนุมัติแล้ว, เอกสารแบบร่างของแผนอื่น, Blanket Order ที่แผนสร้างไว้)
3. ถ้าต่ำกว่า Safety Stock สร้างข้อเสนอ ปัดตาม Minimum Batch / Batch Multiple
4. สินค้าที่ผลิต → ระเบิด BoM (phantom ระเบิดทะลุ) แล้วคำนวณชั้นถัดไป

สถานะแผน: **Draft → Computed → Confirmed → Done** (และ Cancelled)

### คำนวณซ้ำ

คำนวณซ้ำได้ตอน Draft / Computed / **Confirmed** ระบบจะ:

- ลบข้อเสนอที่ยัง **Proposed** แล้วคำนวณใหม่
- เก็บข้อเสนอที่ **Approved / Done** ไว้และหักออกจากความต้องการ
- ข้อเสนอที่ **Rejected** ต้องปฏิเสธใหม่หากยังไม่ต้องการ

ผลสรุปและคำเตือน (เช่น "ไม่มี vendor", "สายผลิตไม่ได้เลือกในแผนนี้") แสดงใน chatter ของแผน

### แท็บ Demand และการแก้ค่าพยากรณ์

แท็บ **Demand** (หรือเมนู **Demand**) แสดงความต้องการรายสัปดาห์แยกตาม Source:

| Source | ความหมาย |
|---|---|
| Delivery | ใบส่งของค้างปลายทางลูกค้า |
| Forecast | ส่วนที่พยากรณ์เกินกว่าใบส่งของ |
| Dependent | วัตถุดิบที่ต้องใช้ (จาก MO เปิด หรือจากข้อเสนอผลิตชั้นบน) |

แก้ **Manual Qty** ในบรรทัด Forecast ได้ ระบบจะใช้ค่านี้แทนค่าเฉลี่ย (นับเป็น max(ใบส่งของ, Manual) ไม่บวกซ้อน) แล้วกด Compute ใหม่

## 6. ตรวจและอนุมัติข้อเสนอ

เมนู **Suggestions** (หรือปุ่มสถิติ Suggestions บนแผน)

| คอลัมน์ | ความหมาย |
|---|---|
| Action | Make (ผลิต) / Buy (ซื้อ) |
| Qty | จำนวนที่เสนอ แก้ได้ในตาราง |
| Needed By | วันที่ของต้องพร้อม (วันแรกของสัปดาห์ที่ขาด) |
| Order / Start By | วันที่ต้องเริ่มสั่ง/ผลิต = Needed By − lead time |
| Late | วันสั่งเลยมาแล้ว ระบบตั้งเป็นวันนี้และติดธง |
| Production Line / Vendor | สายผลิตของ MO / vendor ของ PO |
| BoM Level | ชั้น BoM (0 = สินค้าขาย) |
| Shortage | ยอดที่ขาดก่อนปัดขึ้นตาม batch (ฟอร์มข้อเสนอมีประโยคอธิบายด้านบน เช่น "On hand 120 + incoming 40 - demand 300 = ...") |
| Document / Document Status | เอกสารที่สร้างจากข้อเสนอ (MO, Blanket Order หรือ PO) และสถานะ กดปุ่มลูกศรท้ายแถวเพื่อเปิดเอกสาร |
| Pegged To | วัตถุดิบนี้มาจากข้อเสนอผลิตตัวไหน |

ปุ่มบนตาราง: **Approve / Reject / Reset to Proposed** (เลือกหลายบรรทัดได้) เมนู Suggestions เปิดมาพร้อมตัวกรอง **To Review** (ข้อเสนอที่ยังเป็น Proposed) ตัวกรองอื่น: Make / Buy / Late / Approved / **No Document Yet / No Vendor / Has Document** จัดกลุ่มตามสายผลิต / vendor / level / **Document Status / Blanket Order** ได้ คอลัมน์ที่ใช้น้อย (BoM Level, On Hand, Incoming, Demand, Projected) ซ่อนไว้ เปิดได้จากปุ่มเลือกคอลัมน์

สถานะ: **Proposed → Approved → Done** หรือ **Rejected**

> ข้อเสนอที่ Rejected จะไม่ถูกนับและไม่บล็อกการสร้างเอกสารของรายการอื่น

## 7. สร้าง MO / Blanket Order แบบร่าง

ที่แผนกด **Create Documents** (หรือเลือกข้อเสนอในเมนู Suggestions แล้วเรียกจาก Action) หน้าต่างแบ่งสรุปเป็นสองส่วนก่อนสร้าง: **Will be created** (กี่ MO กี่ Blanket Order/RFQ vendor ไหน) และ **Needs attention** (รายการที่ข้าม/ถูกบล็อก พร้อมวิธีแก้)

| ประเภท | สร้างเป็น | หมายเหตุ |
|---|---|---|
| Make | **MO สถานะ Draft** | Origin = เลขแผน, Deadline = Needed By, เริ่มตาม Order / Start By ไม่ confirm |
| Buy | **Blanket Order สถานะ Draft** (ค่าเริ่มต้น) หรือ **RFQ สถานะ Draft** | เลือกได้ทุกครั้งที่ช่อง *Buy Suggestions Become* รวมบรรทัดตาม vendor หนึ่งใบต่อ vendor ต่อการกดหนึ่งครั้ง สร้างใบใหม่เสมอ ไม่ต่อเข้าใบเดิม |

### เลือก Blanket Order หรือ RFQ

- **Blanket Order** เป็นข้อตกลงกับ vendor ฝ่ายจัดซื้อตรวจราคา กด Confirm เอง (เลข BO-... ออกตอน Confirm) แล้วออก PO จากข้อตกลงนี้ภายหลัง
- **RFQ** คือใบสั่งซื้อฉบับร่างหนึ่งใบต่อ vendor ใช้ส่งให้ vendor ทันที (พฤติกรรมเดิม)

ค่าที่ระบบใส่ใน **Blanket Order**:

| ช่อง | ค่า |
|---|---|
| Vendor / Origin | vendor ของข้อเสนอ / เลขแผน |
| Type | ประเภท Blanket Order ของบริษัท (Quantities = Set quantities manually) |
| Currency | สกุลเงินของ Blanket Order ล่าสุดของ vendor นี้ → สกุลเงินจัดซื้อของ vendor → สกุลเงินบริษัท |
| Operation Type (รับสินค้า) | ของ Blanket Order ล่าสุดของ vendor นี้ **ถ้าอยู่ในคลังที่แผนนับเป็น supply** มิฉะนั้นใช้ใบรับของของคลังแรกในแผน |
| Ordering Date / Delivery Date / Deadline | วันนี้ / Needed By ที่เร็วที่สุด / สิ้นวันสุดท้ายของแผน |
| Product / Quantity / Unit | สินค้า / จำนวน (แปลงเป็นหน่วยซื้อ) / หน่วยซื้อของสินค้า |
| Unit Price | 1) ราคาใน Vendor Pricelist 2) บรรทัด Blanket Order ล่าสุดของ vendor+สินค้า 3) บรรทัด PO ที่ยืนยันล่าสุด 4) **0 และแจ้งว่าไม่พบราคา** |
| Analytic | บรรทัด Blanket Order ล่าสุดของสินค้าที่มี analytic → บรรทัด PO ล่าสุดที่มี → ว่างและแจ้ง |

> Blanket Order ที่สร้างอยู่สถานะ **Draft** เสมอ ฝ่ายจัดซื้อต้องตรวจราคา (บรรทัดที่ราคา 0 จะ Confirm ไม่ได้) และ analytic ก่อนกด Confirm เอง PO ที่ออกจาก Blanket Order คัดลอก analytic จากบรรทัดนี้ ถ้าว่าง PO จะถูกระบบบัญชีปฏิเสธ

### กติกาที่ควรรู้

- ข้อเสนอที่ **Proposed** จะถูกอนุมัติให้อัตโนมัติในหน้านี้ ที่ **Rejected** ถูกข้าม
- **ไม่มี Production Line** → หยุดและแจ้งชื่อสินค้า ต้องกรอกที่พารามิเตอร์สินค้าแล้ว Compute ใหม่
- **ไม่มี vendor** → ข้าม แจ้งในสรุป ไม่ได้หยุดทั้งชุด
- **MO หรือ Blanket Order ที่ระบบบัญชีไม่ยอมให้สร้าง** (ดูหัวข้อ Analytic ด้านล่าง) → ข้ามใบนั้นพร้อมเหตุผล ใบอื่นยังสร้างต่อ ข้อเสนอนั้นคงสถานะ Approved เพื่อให้แก้แล้วลองใหม่ได้
- **สร้างซ้ำไม่ได้** ข้อเสนอที่มีเอกสารแล้วจะถูกข้าม
- หลังสร้างแล้วระบบกลับมาหน้าแผน ปุ่มสถิติ (Manufacturing Orders / Blanket Orders / Purchase Orders) และแถบ "ขั้นตอนถัดไป" อัปเดตทันที แจ้งเตือนเป็นสีเหลืองถ้ามีรายการที่ไม่ได้สร้าง สรุปผลพร้อมลิงก์ไปยังเอกสารโพสต์ใน chatter (Blanket Order ฉบับร่างยังชื่อ "New" จึงแสดงเป็น Blanket Order (draft) - ชื่อ vendor)
- แผนเป็น **Confirmed** (ยังมีข้อเสนอค้าง) หรือ **Done** (หมดแล้ว)

### การเชื่อมระหว่างแผนกับเอกสาร

- บนแผน: ปุ่ม **Manufacturing Orders / Blanket Orders / Purchase Orders** (ซ่อนเมื่อเป็น 0) Purchase Orders = RFQ ที่แผนสร้างตรง + PO ที่ออกจาก Blanket Order ของแผน
- บน **MO, Blanket Order และ PO** มีปุ่ม **Production Plan** กดกลับไปแผนต้นทาง
- บนข้อเสนอ: คอลัมน์ Document / Document Status และปุ่ม **Open Document**

### Blanket Order นับเป็น supply

Blanket Order ไม่สร้าง stock move จนกว่าจะออก PO แล้วยืนยัน ถ้าไม่นับ การ Compute ครั้งต่อไปจะเสนอซื้อซ้ำ ระบบจึงนับ **จำนวนคงเหลือของบรรทัด Blanket Order ที่แผนสร้าง** (จำนวน − จำนวนที่ออก PO ที่ยืนยันแล้ว) เป็นของเข้า ณ วัน Needed By ของข้อเสนอนั้น ทั้งในแผนเดิมและแผนอื่น

- PO ที่ยืนยันแล้วจะนับผ่านใบรับของตามปกติ ไม่นับซ้ำ PO ฉบับร่างอยู่ในจำนวนคงเหลือของ Blanket Order
- ไม่นับถ้า Blanket Order **Closed / Cancelled** หรือเลย **Deadline**
- **Blanket Order ที่ทำด้วยมือไม่นับเด็ดขาด** (ของเดิมมีค้างเปิดอยู่มาก)

### Analytic บน MO, Blanket Order และ PO

บริษัทบังคับ **Analytic (BU + Production)** บน MO ระบบจึงคัดลอก analytic จาก **MO ล่าสุดของสินค้านั้น** ให้อัตโนมัติ

- สินค้าที่ไม่เคยมี MO → ระบบสร้างไม่ได้ จะแจ้งในสรุป ให้สร้าง MO เองหนึ่งใบหรือปรับ analytic แล้วลองใหม่
- ตรวจ/แก้ analytic บน MO draft ก่อนกด Confirm ได้เสมอ
- **Blanket Order** คัดลอก analytic จากบรรทัด Blanket Order / PO ล่าสุดของสินค้า ถ้าไม่พบจะแจ้ง ให้กรอกที่บรรทัดก่อน Confirm
- **RFQ ที่ระบบสร้างยังไม่มี analytic** ฝ่ายจัดซื้อต้องกรอก (BU / Department / Section) ตอน Confirm RFQ

### ปุ่มสถิติบน MO

บน MO ที่สร้างจากแผนมีปุ่ม **Production Plan** กดเพื่อเปิดแผนต้นทาง

## 8. จัดคิว (Schedule)

กดปุ่ม **Schedule** ที่แผน (ใช้ได้เมื่อแผนไม่ใช่ Draft/Cancelled) ระบบวาง workorder ที่ยังเปิดอยู่ (pending / waiting / ready / progress) ของ MO ที่ Confirmed / In Progress ลง workcenter

### หลักการจัดคิว

- **ลำดับ MO:** deadline (ไม่มี deadline ไว้ท้าย) → priority → วันเริ่ม
- **ลำดับใน MO เดียวกัน:** ตามลำดับ operation (หรือ dependency ถ้าเปิดใช้)
- **Workcenter ทำทีละงาน** ไม่ซ้อนกัน
- **เวลาทำงาน** ตาม working schedule ของ workcenter ข้ามนอกเวลา วันหยุด และพักเที่ยง
- **ระยะเวลา:**
  - ใช้ **เวลาจริงจากประวัติ** (ต่อหน่วย × จำนวน) เมื่อมี workorder ที่ทำเสร็จครบตามเกณฑ์ใน Settings
  - ไม่ถึงเกณฑ์ → ใช้ **เวลามาตรฐาน × Expected Duration Factor**
  - คอลัมน์ Duration Source บอกว่าบรรทัดนั้นใช้อะไร
- **งานที่กำลังทำ (progress):** ล็อกไว้ ไม่ถูกย้าย แสดงงานที่เหลือต่อคิวตั้งแต่ **เวลาปัจจุบัน** ทีละงานต่อ workcenter วันเริ่มจริงยังอยู่ใน workorder
- **MO ที่ไม่มี workorder** (BoM ไม่มี operation) และ **MO แบบ Draft** ไม่เข้าคิว

### Schedule ซ้ำ

กด Schedule อีกครั้ง ระบบลบเฉพาะบรรทัดที่ไม่ล็อก/ไม่ถูกแก้มือ แล้ววางใหม่ บรรทัดที่ **Locked** หรือ **Manual** อยู่คงเดิมและกันที่ไว้ให้

ตารางผลอยู่ที่เมนู **Schedule** (กรอง Late / Locked / Manual, จัดกลุ่มตาม Workcenter / Status)

## 9. Gantt

กด **Open Gantt** ที่แผน หรือเมนู **Gantt**

- **แถว** = workcenter จัดกลุ่มตามรหัส (PD1 = QC/ประกอบสุขภัณฑ์, PD2 = เฟอร์นิเจอร์/บันได) **แท่ง** = งานหนึ่งรายการ
- เส้นแนวตั้งสีส้ม = เวลาปัจจุบัน
- แถบใต้ชื่อ workcenter = **นาทีที่จัดแล้ว / นาทีกำลังการผลิต** ของวันนั้น
- สลับ **Day / Week** ได้ ปุ่ม Today / ก่อนหน้า / ถัดไป เลื่อนช่วงเวลา
- ตัวกรอง: แผน, สายผลิต, workcenter, **Late only**

### สีของแท่ง

| ลักษณะ | ความหมาย |
|---|---|
| น้ำเงิน | ปกติ |
| แดง | จบหลัง deadline (Late) |
| เทา | ล็อก (กำลังทำ หรือ planner ล็อก) ลากไม่ได้ |
| ขอบเข้ม | แก้ด้วยมือ (Manual) |

### การใช้งาน

| ทำอะไร | วิธี |
|---|---|
| ดูรายละเอียด | วางเมาส์บนแท่ง (MO, สินค้า, จำนวน, operation, เวลา, deadline) |
| เปิด MO | คลิกแท่ง |
| ย้ายเวลา | ลากแท่งในแถวเดิม |
| ปรับระยะเวลา | ลากขอบขวาของแท่ง |
| จัดใหม่ทั้งหมด | ปุ่ม **Re-schedule** |
| เขียนลง workorder | ปุ่ม **Apply** (Manager) |

- ลากข้ามแถวไม่ได้ (workcenter มาจาก operation)
- เวลาที่ลากไป **ถูกปัดเข้าเวลาทำงาน** ของ workcenter อัตโนมัติ (เช่น ลากไปก่อน 08:00 จะเริ่ม 08:00) ระยะเวลาไม่เปลี่ยนเมื่อย้าย
- แท่งที่แก้มือจะไม่ถูกย้ายเมื่อกด Re-schedule
- แท่งซ้อนกันใน workcenter เดียวกันจะเตือนด้วยสี ไม่บล็อก ตัดสินใจเองแล้วกด Re-schedule ได้

## 10. Apply ลง workorder

ปุ่ม **Apply Schedule** (Planning / Manager) ที่แผน หรือ **Apply** บน Gantt เขียน **วันเริ่ม/วันจบ** ลง workorder จริง และปรับวันที่ของ MO ตาม ระบบถามยืนยันก่อน

- **ไม่เปลี่ยนสถานะ** ของ workorder หรือ MO
- ทำทีละ **50 MO ต่อครั้ง** ถ้ายังเหลือจะแจ้งจำนวนที่เหลือ กด Apply ซ้ำจนหมด (ทำต่อได้ ไม่เสียงาน)
- **ข้าม** workorder ที่กำลังทำ และข้าม MO ที่ **มี stock move ที่ done แล้ว** (เพราะ Odoo จะเปลี่ยนวันที่ของ move ทุกตัวใน MO ตามวันที่ใหม่ ซึ่งทำให้ประวัติสต็อกเพี้ยน) เหตุผลแสดงใน chatter ของแผน
- วันที่ของ move ที่ยังเปิดอยู่ (วัตถุดิบ/สินค้าสำเร็จรูปของ MO นั้น) จะเปลี่ยนตามวันที่แผน ซึ่งเป็นพฤติกรรมปกติของ Odoo

> แก้ด้วยมือบน Gantt หลัง Apply แล้ว บรรทัดนั้นกลับเป็น Proposed ต้อง Apply อีกครั้ง

## 12. Dashboard

เมนู **Planning → Dashboard** เป็นหน้าแรกเมื่อเปิดแอป Planning ใช้ตอบสองคำถาม: "วันนี้มีอะไรต้องทำ" (ผู้วางแผน) และ "โรงงานงานล้นตรงไหน" (ผู้จัดการโรงงาน)

- หน้านี้ **ดูอย่างเดียว** ไม่แก้ข้อมูล ไม่เปลี่ยนสถานะ ไม่สร้างเอกสาร ทุกการกดเป็นการเปิดรายการที่มีอยู่แล้ว
- ตัวเลขทั้งหมดเป็นของ **แผนที่เลือกแผนเดียว** ไม่รวมข้ามแผน (แผนซ้อนช่วงเวลากัน ถ้ารวมจะนับซ้ำ) ค่าเริ่มต้นคือแผนล่าสุดของบริษัท เปลี่ยนแผนได้จากช่องเลือกด้านบน ระบบจำแผนที่เลือกล่าสุดไว้ในเบราว์เซอร์
- แถบด้านบนมีสถานะแผน ช่วงวันที่ ผู้วางแผน ข้อความ "ขั้นตอนถัดไป" และปุ่ม **Open plan**, **Gantt**, **Refresh**
- กดที่การ์ดหรือแท่งกราฟเพื่อเปิดรายการ จำนวนแถวในรายการเท่ากับตัวเลขที่กด

### การ์ด

| การ์ด | ความหมาย | ต้องทำอะไร |
|---|---|---|
| **Suggestions to review** | ข้อเสนอสถานะ Proposed ที่ยังไม่ได้ตัดสินใจ | อนุมัติหรือปฏิเสธ |
| **Approved, no document yet** | อนุมัติแล้วแต่ยังไม่มี MO / Blanket Order / RFQ | กด Create Documents ในแผน |
| **Late suggestions** | ข้อเสนอที่ยังเปิดอยู่ ซึ่งวันที่ต้องเริ่ม/สั่งซื้อผ่านไปแล้วตอนคำนวณแผน | เร่งทำก่อน |
| **Buy without vendor** | ข้อเสนอซื้อที่ยังเปิดอยู่และไม่มี vendor | ใส่ vendor ก่อนสร้างเอกสาร |
| **Products short** | จำนวนสินค้า (นับไม่ซ้ำ) ที่ข้อเสนอที่ยังเปิดอยู่บอกว่าของขาด รายการที่เปิดจะจัดกลุ่มตามสินค้า | ดูว่าสินค้าไหนขาด |
| **Work orders finishing late** | บรรทัดคิวงานที่จะเสร็จหลัง deadline ของ MO | ย้ายคิวใน Gantt หรือแจ้งฝ่ายขาย |
| **Schedule lines not applied** | บรรทัดคิวงานที่ยังไม่ได้ Apply ลง workorder | Manager กด Apply Schedule |

การ์ดที่เป็น 0 จะเป็นสีเทา แต่ยังกดได้

### กราฟ

| กราฟ | อ่านอย่างไร | กดแล้วเปิด |
|---|---|---|
| **Load vs capacity by week** | แท่ง = ชั่วโมงงานที่จัดคิวไว้ต่อสัปดาห์ เส้น = ชั่วโมงที่ workcenter ทำงานได้ ส่วนสีแดง = งานเกินกำลังการผลิต | คิวงานของสัปดาห์นั้น |
| **Busiest work centers** | 10 workcenter ที่ภาระงานเทียบกำลังการผลิตสูงสุดตลอดช่วงแผน เส้นประ = 100 % แท่งสีแดง = เกิน 100 % | คิวงานของ workcenter นั้น |
| **On-time schedule** | สัดส่วน MO ที่จัดคิวแล้วเสร็จตรงเวลา MO นับว่าล่าช้าเมื่อมีบรรทัดคิวงานอย่างน้อยหนึ่งบรรทัดล่าช้า | บรรทัดคิวงานที่ล่าช้า |
| **Suggestions by release week** | จำนวนข้อเสนอที่ยังเปิดอยู่ แยก Make / Buy ตามสัปดาห์ที่ต้องเริ่มผลิตหรือสั่งซื้อ | ข้อเสนอของสัปดาห์นั้น |
| **Document progress** | ข้อเสนอที่ไม่ถูกปฏิเสธ แยกตามสถานะเอกสาร: ยังไม่มีเอกสาร / ร่าง / กำลังดำเนินการ / เสร็จ | ข้อเสนอที่มีสถานะเอกสารนั้น |

หมายเหตุ:

- กราฟภาระงานแสดงตั้งแต่วันจันทร์ของสัปดาห์แรกของแผน ไปจนถึงวันสิ้นสุดแผนหรือวันจบของงานสุดท้าย (แล้วแต่อย่างไหนช้ากว่า) สูงสุด 26 สัปดาห์ ถ้าคิวงานยาวกว่านั้นจะมีข้อความบอกใต้ชื่อกราฟ
- ถ้าแผนยังไม่ได้กด **Schedule** กราฟภาระงานและกราฟตรงเวลาจะขึ้นข้อความให้จัดคิวก่อน
- ผู้ใช้ MRP ทั่วไปเปิดหน้านี้และเปิดรายการได้ แต่แก้ไขไม่ได้

## 13. ข้อควรระวังและแก้ปัญหาเบื้องต้น

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| "ไม่มีสายผลิต" ตอนสร้างเอกสาร | สินค้าไม่เคยมี MO และไม่มีพารามิเตอร์ ตั้ง **Production Line** ที่ Product Parameters แล้ว Compute ใหม่ หรือ Reject ข้อเสนอนั้น |
| ข้อเสนอ Buy "ไม่มี vendor" | ตั้ง vendor ที่สินค้า หรือใส่ **Vendor Override** ในพารามิเตอร์ ข้อเสนอแบบนี้ถูกข้ามตอนสร้าง Blanket Order / RFQ |
| Blanket Order บรรทัดราคา 0 / ไม่มี analytic | ไม่พบราคาหรือ analytic จากประวัติ กรอกที่บรรทัด Blanket Order ก่อน Confirm (Confirm ไม่ได้ถ้าราคาเป็น 0) |
| "ไม่ได้ตั้งค่าประเภท Blanket Order" | สร้างประเภทที่ จัดซื้อ > การกำหนดค่า > ประเภทข้อตกลง ที่ Quantities = Set quantities manually |
| Compute แล้วยังเสนอซื้อซ้ำทั้งที่มี Blanket Order | Blanket Order ทำด้วยมือไม่ถูกนับ หรือ Blanket Order ถูก Close / Cancel / เลย Deadline หรือใบรับของไปเข้าคลังที่ไม่ได้อยู่ใน Supply Warehouses ของแผน |
| สร้าง MO ไม่ได้ ติด Analytic | บริษัทบังคับ analytic บน MO สินค้านั้นไม่เคยมี MO ให้คัดลอก สร้าง MO เองหนึ่งใบเพื่อให้มีต้นแบบ หรือแจ้งฝ่ายบัญชี |
| Compute แล้วข้อเสนอเยอะมาก | ตรวจ Supply Warehouses ว่าครบ ตรวจสินค้า Do not plan ตรวจ Safety Stock และค่าพยากรณ์ที่ Demand |
| ข้อเสนอเลยวันสั่ง (Late) เยอะ | lead time ยาวกว่าเวลาที่เหลือ ปรับ lead time ในพารามิเตอร์ หรือเลื่อนกำหนดส่ง |
| Gantt ว่าง | ยังไม่ได้กด Schedule หรือแผนนั้นไม่มี workorder ที่เปิดอยู่ (MO ไม่มี operation ไม่เข้าคิว) |
| Schedule ไปไกลมาก (เป็นเดือน) | งานค้างเกินกำลังผลิตจริง ดู Load vs Capacity เพิ่มกะ/แบ่งสาย หรือลดงาน |
| แท่งซ้อนกันบน Gantt | เกิดจากการลากแก้ด้วยมือ กด Re-schedule |
| Apply ข้ามบาง MO | MO นั้นกำลังทำอยู่ ไม่เปิดแล้ว หรือมี stock move done แล้ว (ดูหัวข้อ 10) |
| แผนอื่นสร้าง MO draft ไว้แล้ว แต่แผนนี้ยังเสนอวัตถุดิบ | ถูกต้อง ระบบนับ MO draft ของแผนอื่นเป็นของเข้า แต่ยังวางแผนวัตถุดิบของ MO นั้นให้ |

### ข้อจำกัดที่รู้

- **Re-schedule ลบบรรทัดที่ Apply แล้ว** และสองแผนสามารถ Apply วันที่ต่างกันลง workorder เดียวกันได้ ควรใช้แผนจัดคิวเพียงแผนเดียวต่อสายผลิตในเวลาเดียวกัน
- เอกสารแบบร่างที่สร้างด้วยมือ (ไม่ได้มาจากแผน) **ไม่ถูกนับ** เป็นของเข้า เพราะมี RFQ และ Blanket Order ค้างที่ไม่ได้ใช้จริงปนอยู่มาก
- หน้า Operation Time History เริ่มนับที่ 2026-04-01 เสมอ ไม่ตามวัน cut-off ใน Settings
- RFQ ที่ระบบสร้างไม่มี analytic ต้องกรอกตอน Confirm (Blanket Order คัดลอกจากประวัติให้)
