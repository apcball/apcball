# Buz Reverse Manufacturing

Reverse Manufacturing (disassembly) for Odoo 17 Enterprise, built on
`mrp.production` — **not** on `mrp.unbuild` — so the full manufacturing
framework is reused: work orders, work centers, routing, tablet view,
employee time tracking, labor cost and OEE.

```
Normal:   Components -> Work Orders -> Finished Product
Reverse:  Finished Product -> Work Orders -> Recovered Components
```

## How it works

- A **Reverse BOM** (`mrp.bom` type *Reverse Manufacturing*) lists the
  input product (BOM product) and the components expected to be recovered
  (BOM lines), each with a recovery %, a destination location and a scrap
  policy. Operations on the BOM drive the work orders as usual.
- A **Reverse Manufacturing Order** (menu *Manufacturing → Operations →
  Reverse Manufacturing Orders*, sequence `RMO00001`) consumes the input
  product with a single raw move and produces every recovery line as a
  by-product-style finished move with a `cost_share`.
- **Costing**: total recoverable cost = input product valuation (real
  FIFO/AVCO layers) + work order labor/operation cost + extra cost. It is
  distributed over the recovered components by the chosen allocation
  method; standard `stock.valuation.layer` records and journal entries
  are generated by core `stock_account`.

## Allocation methods

| Method | Basis per line |
|---|---|
| BOM Cost Ratio (default) | standard price × actual qty |
| Percentage | user-entered % (must sum to 100) |
| Quantity | actual recovered qty |
| Weight | product weight × actual qty |
| Manual Amount | user-entered amount, normalized to % |

Percentages are normalized to exactly 100.00; the last line absorbs the
rounding residual.

## Recovery & scrap

`actual qty = expected qty × recovery %`. Any shortfall
(`expected − actual`) is scrapped automatically on *Mark Done* (policy
*Auto Scrap Shortfall*). The scrap consumes from the virtual production
location: full traceability, zero valuation impact — the whole cost stays
on the recovered goods.

## Security

| Group | Rights |
|---|---|
| Reverse Manufacturing User | create orders, start/complete work orders, edit lines |
| Reverse Manufacturing Supervisor | + see costs, validate |
| Reverse Manufacturing Manager | + cancel, reset, delete lines, cost override |

## Installation

1. Deploy: `bash scripts/deploy.sh dev buz_reverse_manufacturing`
2. Restart Odoo, then install *Buz Reverse Manufacturing* (deps:
   mrp, mrp_account, mrp_workorder, stock_account, hr, mail — Enterprise).
3. Assign the security groups to users.

## Usage

1. Create a Reverse BOM for the product to disassemble.
2. Create a Reverse Manufacturing Order, pick the product, quantity and
   reverse BOM — recovery lines are generated automatically.
3. Confirm, process work orders (tablet supported).
4. Adjust actual quantities, destinations and lots, then **Mark Done**.
5. Print the *Reverse Manufacturing Order* PDF report from the order.

## Tests

`tests/` covers BOM guard, allocation methods, FIFO/AVCO valuation,
journal entries, scrap, work order costing and security. Run against the
isolated test DB first (`docker-compose.test.yml`); the live-DB test
runner has irreversible side effects.

## Limitations

- Reverse orders cannot be split into backorders (by design).
- One input product per order.
- Serial-tracked recovered products need one recovery line per unit.
