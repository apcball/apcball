# จัดส่ง Shopee เป็นชุดและดาวน์โหลดใบปะหน้า

เวอร์ชันโมดูล: 17.0.2.2.0 • สำหรับ Odoo 17

## สถานะรุ่นนี้

เป็นโค้ดสำหรับนำไปติดตั้งและทดสอบบนฐานข้อมูลทดสอบก่อนใช้งานจริง ยังไม่ได้ติดตั้งบน Odoo หรือเรียกบัญชี Shopee จริงในงานนี้ ชุดทดสอบออฟไลน์ตรวจตรรกะและคำขอที่จำลองไว้ ไม่ได้ยืนยันว่า Shopee ทุกประเทศ/ขนส่งใช้รูปแบบเดียวกัน

## ความสามารถที่เพิ่ม

- เลือกออเดอร์หลายรายการเพื่อสร้างชุดจัดส่ง สูงสุด 200 ออเดอร์ต่อชุด
- แต่ละชุดอยู่ในบริษัทเดียว รองรับหลายร้านในบริษัทนั้น โดยเรียก API ตามร้านของแต่ละออเดอร์
- โหลดตัวเลือกนำส่งเอง (dropoff) และนัดรับ (pickup) จาก API ให้เลือกอย่างชัดเจน
- ปุ่มเลือกนำส่งเองทั้งชุดทำงานเฉพาะออเดอร์ที่มีตัวเลือก dropoff เดียว ถ้ามีหลายสาขาต้องเลือกเอง
- ยืนยันเอกสารขาย Odoo ก่อนจัดส่งได้ โดยเปิดไว้เป็นค่าเริ่มต้น รายการที่สินค้าไม่ครบหรือยังใช้ SHOPEE_UNMAPPED จะถูกพัก
- ตรวจสถานะออเดอร์และตัวเลือกขนส่งใหม่ก่อนสั่งจัดส่ง
- จัดส่งเบื้องหลัง แยกงานและผลของแต่ละออเดอร์ จึงไม่ต้องรอ API ทั้งชุดในหน้าเว็บ
- ติดตามเลขพัสดุ สร้างงานใบปะหน้า ตรวจสถานะ แล้วดาวน์โหลด PDF ของ Shopee
- เลือก Normal หรือ Thermal ได้ตามที่ API ของขนส่งรองรับ ไม่ปรับขนาด PDF ต้นฉบับ
- ดาวน์โหลด PDF รายออเดอร์ หรือ ZIP รวมไฟล์ที่พร้อม พร้อม results.csv ของทุกออเดอร์
- ออเดอร์เดิมในหลายชุดใช้ shipping job เดียวกัน ป้องกันการสร้างงานซ้ำในโมดูล
- บันทึกเจตนาก่อนเรียก API จัดส่ง หาก timeout/โปรเซสหยุด จะพักตรวจสถานะ ไม่ส่งคำสั่งเดิมซ้ำอัตโนมัติ

## ติดตั้ง/อัปเกรด

1. สำรองฐานข้อมูลและ filestore แล้วใช้ฐานข้อมูลทดสอบเป็นลำดับแรก
2. แตก ZIP จะได้โฟลเดอร์ `shopee_connector` ให้นำไปแทนโมดูลชื่อเดียวกันใน addons path ห้ามวางซ้อนเป็น `shopee_connector/shopee_connector`
3. ติดตั้ง `requests` ใน Python environment ของ Odoo (และ `openpyxl` หากใช้การนำเข้า/ส่งออกสต็อกเดิม)
4. รีสตาร์ต Odoo และอัปเกรดโมดูลจาก Apps หรือใช้คำสั่งตัวอย่างด้านล่าง โดยปรับฐานข้อมูลและ config ให้ตรงระบบ

```bash
odoo-bin -c /path/to/odoo.conf -d TEST_DATABASE -u shopee_connector --stop-after-init
```

5. ใช้บัญชีที่มีสิทธิ์ Sales Manager การเข้าถึงชุดจัดส่ง งานจัดส่ง ตัวเลือก และไฟล์ ใช้สิทธิ์ Odoo และกฎแยกบริษัท
6. ตรวจ Scheduled Actions ว่า `Shopee: Shipping and Labels` เปิดใช้งาน และมี cron worker ทำงาน
7. เชื่อมร้าน Sandbox และตรวจสิทธิ์ Logistics/Shipping Documents ของแอปก่อนทดสอบ API ของร้าน

## วิธีใช้

1. ไปที่ **Shopee → Orders** นำเข้าออเดอร์จริงจากร้านที่เชื่อมต่อไว้ แล้วตรวจสินค้า ราคา และยอดขายก่อน
2. เลือกหลายออเดอร์ → เมนู **Action → Shopee: Arrange shipment and labels / จัดส่งและใบปะหน้า**
3. ระบบเปิดหน้าชุดจัดส่ง รอ worker โหลดตัวเลือก แล้วรีเฟรชหน้าเว็บ
4. หากนำส่งเอง ใส่ชื่อผู้ส่งในหน้าชุดเมื่อขนส่งต้องการ แล้วกด **Select dropoff where unambiguous / เลือกนำส่งเอง**
5. ถ้านัดรับหรือมีหลายสาขา กด **Options / ตัวเลือก** ที่ออเดอร์ เลือกที่อยู่/เวลานัดรับหรือสาขา เลือกชนิดใบปะหน้า และบันทึก กลับหน้าชุดผ่าน breadcrumb
6. ตรวจรายการให้ครบ แล้วกด **Queue selected options / สั่งจัดส่งทั้งชุด** การยืนยันปุ่มนี้จะอนุญาตให้ worker ยืนยันเอกสารขายตามตัวเลือก และสั่งจัดส่งบน Shopee
7. รอ worker และรีเฟรชเพื่อดูเลขพัสดุ/ผลการจัดส่ง หากเป็น **Label ready** กด **Download ready labels (ZIP)**
8. แตก ZIP แล้วพิมพ์ PDF ด้วยขนาดจริง 100% ตามกระดาษของขนส่ง ตรวจ `results.csv` เพื่อทราบรายการที่ยังไม่มีใบปะหน้า

ไฟล์ ZIP อาจมีเพียงบางออเดอร์หากออเดอร์อื่นยังทำงานหรือมีข้อผิดพลาด หน้าจอจะแสดงจำนวนที่รวมให้แล้ว ไม่ได้รวม PDF ทุกใบเป็นเอกสาร PDF เดียว และไม่ได้สั่งเครื่องพิมพ์โดยอัตโนมัติ

## ความหมายของสถานะ

| สถานะ | สิ่งที่ต้องทำ |
|---|---|
| Loading options | รอโหลดตัวเลือกแล้วรีเฟรช |
| Select shipping option | เลือกตัวเลือกจัดส่งแล้วกดสั่งจัดส่ง |
| Queued for shipment | รอ worker ตรวจและส่งคำสั่ง |
| Check shipment result | มีคำขอที่ผลไม่ชัดเจน ตรวจ Seller Centre แล้วกด Reload / Check result เพื่ออ่านสถานะใหม่ |
| Shipment arranged | จัดส่งได้รับการยืนยันหรือพบว่าจัดไว้แล้ว รอเลขพัสดุและใบปะหน้า |
| Preparing label | ระบบส่งคำขอสร้างใบปะหน้าแล้ว กำลังตรวจผล |
| Label ready | ดาวน์โหลดได้ |
| Needs attention | อ่านข้อความสาเหตุ แก้ไข แล้ว Reload หรือ Regenerate label ตามกรณี |

### เมื่อพบปัญหา

- **ตัวเลือกนัดรับหมดอายุ:** Reload แล้วเลือกตัวเลือกใหม่
- **Timeout/5xx ขณะจัดส่ง:** ระบบไม่ยิง ship_order ซ้ำ ตรวจ Seller Centre ก่อน หากจัดส่งสำเร็จแล้ว กด Reload เพื่อไปขั้นตอนใบปะหน้า หากยังไม่ชัดเจนให้จัดการใน Seller Centre รุ่นนี้ไม่มีปุ่มล้างสถานะไม่แน่นอนเพื่อฝืนส่งใหม่
- **เลขพัสดุยังไม่พร้อม:** ระบบตรวจใหม่เป็นรอบ สูงสุด 20 รอบ หากยังไม่พร้อมจะขึ้น Needs attention ให้กด Reload ภายหลัง
- **งานใบปะหน้ากำลังทำ:** ตรวจเป็นรอบ ไม่รอค้างในหน้าเว็บ หลัง 20 รอบจะพักให้ตรวจสอบ
- **สร้างใบปะหน้าล้มเหลว:** Reload จะตรวจผลเดิมถ้าเคยส่งคำขอแล้ว; Regenerate label ใช้สร้างใบใหม่สำหรับ shipment ที่จัดแล้ว โดยไม่จัดส่งซ้ำ
- **สิทธิ์ผู้ขอเปลี่ยน:** งานเบื้องหลังทำด้วยผู้ใช้งานที่กดคิว หากถูกปิดบัญชีหรือไม่มีสิทธิ์บริษัท งานจะพัก
- **มีออเดอร์ที่ยังไม่เลือกตัวเลือก:** การกดคิวทั้งชุดจะไม่ผ่านจนเลือกครบสำหรับรายการสถานะ Select shipping option รายการที่ขึ้นข้อผิดพลาดไม่ถูกส่ง

## ขอบเขตและข้อจำกัด

- รองรับออเดอร์ 1 พัสดุเท่านั้น ออเดอร์ที่มีหลาย package จะพักให้จัดการใน Seller Centre
- รองรับ integrated pickup/dropoff; ไม่รองรับ non-integrated carrier, cross-border special forms หรือพารามิเตอร์เพิ่มเติมที่ไม่รู้จัก
- การจัดส่งบน Shopee ไม่ได้กด Validate ใบส่งสินค้า Odoo ไม่ออกใบแจ้งหนี้ และไม่จัดการคืนสินค้า/ยกเลิกให้อัตโนมัติ
- ข้อมูลราคา/ภาษี/ส่วนลดจากตัวนำเข้าเดิมยังต้องตรวจสอบก่อนยืนยัน ไม่มีการกระทบยอดทางบัญชีเพิ่มในรุ่นนี้
- รูปแบบคำขอ Logistics และใบปะหน้ายังต้องตรวจสอบกับแอป Shopee/ประเทศ/ขนส่งจริง หน้าเอกสารทางการตอบ 403 ในสภาพแวดล้อมพัฒนาครั้งนี้
- มี worker ตามรอบทุก 1 นาที สูงสุด 5 งานต่อรอบ แต่ละงานทำหนึ่งขั้นตอน ชุดใหญ่จะใช้หลายรอบ และ API ที่ช้าอาจต้องปรับ cron timeout ในระบบจริง
- ล็อกงานป้องกัน worker ของโมดูลทำซ้ำ และอ่านสถานะใหม่ก่อนส่ง แต่ไม่สามารถล็อกการเปลี่ยนสถานะที่เกิดจาก Seller Centre หรือระบบอื่นได้
- ดาวน์โหลดใบปะหน้ามีข้อมูลส่วนบุคคล ควรกำหนดนโยบายเก็บและลบตามระบบขององค์กร รุ่นนี้ไม่ลบอัตโนมัติ
- เป็นการเพิ่มส่วนจัดส่ง/ใบปะหน้า ไม่ใช่การแก้ทุกข้อจำกัดเดิมของระบบ โดยเฉพาะ Webhook ที่ไม่บังคับลายเซ็นหากไม่ได้ตั้ง secret และการแยกข้อมูลของโมเดลเดิม ควรปิด endpoint ที่ยังไม่ใช้หรือแก้ก่อน production
- ยังไม่ได้เพิ่มตัวนำเข้าออเดอร์ Excel หรือออเดอร์จำลองในรุ่นนี้ ต้องมีตัวอย่าง Excel เพื่อทำ mapping ให้ตรงไฟล์จริง

## ทดสอบ

ผลตรวจในสภาพแวดล้อมนี้: ชุดทดสอบออฟไลน์ 22 กรณีผ่าน ตรวจโครงสร้าง Python, XML และไฟล์ที่ manifest อ้างอิงแล้ว ไม่มี Odoo/PostgreSQL สำหรับรันการติดตั้งหรือ integration tests

```bash
python shopee_connector/qa/test_shipping_offline.py
```

มี Odoo integration tests เพิ่มใน `tests/test_fulfillment.py` แต่ยังไม่ได้รันในงานนี้ ตัวอย่างคำสั่งสำหรับฐานข้อมูลทดสอบ:

```bash
odoo-bin -c /path/to/odoo.conf -d TEST_DATABASE -u shopee_connector --test-enable --test-tags /shopee_connector --stop-after-init
```

ก่อนใช้งานจริงควรผ่าน: ติดตั้ง/อัปเกรด, ทดสอบสิทธิ์แต่ละบริษัท, 1 dropoff, 1 pickup, เลือกหลายออเดอร์ที่มีรายการล้มเหลวปน, timeout หลังส่งคำขอ, กลับมาทำใบปะหน้าต่อโดยไม่จัดส่งซ้ำ และพิมพ์ทดสอบกับขนส่งที่ร้านใช้งานจริง
